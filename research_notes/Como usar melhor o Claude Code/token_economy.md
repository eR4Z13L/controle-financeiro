# Token economy: spending less of a Claude Pro plan in Claude Code (state as of 2026-10-12)

Scope note for the report writer: official docs at code.claude.com were downloaded on 2026-10-12 as raw markdown, so quotes are exact. These living pages reference Claude Code versions up to v2.1.296. The Help Center (support.claude.com) articles were also read on 2026-10-12, and most show "Updated this week". Community sources are marked **[3rd-party]**. Several community sites (finopsllm.com, getunblocked.com, dyb.mataroa.blog, macobserver.com, gigazine.net) did not resolve from this environment. Their figures come only from search-engine summaries, are marked **[unverified]**, and should be treated as indicative at best. Dollar figures are API list prices. ## 1. How do Claude Pro usage limits work right now, and what counts most against them?

### Takeaway
Pro (US$20/month) has two limits: a rolling **5-hour session limit** and a **weekly limit** that resets at a fixed time assigned to the account. One pool covers claude.ai, the Desktop app, IDE extensions and Claude Code. When you hit either limit you wait, or you turn on **usage credits**, which are billed at API rates. On Pro, Fable models and fast mode run *only* on usage credits. The biggest drivers of usage are context size (the whole context is re-sent on every request, including every tool call), cache misses, the model and effort level, and background or parallel agents.

### Cited Findings
- **Two limits, one shared pool.** "Paid plans have two types of usage limits: a session limit that resets every five hours, and weekly limits that reset once every week." Also: "your usage of all different Claude product surfaces (claude.ai, Claude Code, Claude Desktop) counts towards the same usage limit." (Help Center, updated week of 2026-10-12) — [How do usage and length limits work?](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)
- **What affects usage, officially:** "the length and complexity of your conversations, the features you use, which Claude model you're chatting with, and the effort level you've selected." The same article says: "Longer conversations that trigger automatic context management consume more of your usage limit" and "Tools and connectors are token-intensive." — [How do usage and length limits work?](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)
- **Pro plan facts:** US$20/month (US). "Your session-based usage limit will reset every five hours." "Pro plans also have a weekly usage limit that applies across all models. Weekly limits reset at a fixed time each week that is assigned to your account." Anthropic "may limit your usage in other ways, such as weekly and monthly caps or model and feature usage, at our discretion." - **IDE and Desktop count too:** "IDE usage counts toward the same usage limits shared across Claude and Claude Code." When you hit a limit, Pro users can upgrade to Max 5x, enable usage credits, switch to a Console API account, or wait. — [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)
- **API-key trap:** "If you have an ANTHROPIC_API_KEY environment variable set on your system, Claude Code will use this API key for authentication instead of your Claude subscription … resulting in API usage charges." — [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)

They are prepaid, with an optional monthly spend cap, auto-reload and alerts, and they are managed in Settings > Usage. Usage credits do not change reset timing. — [Manage usage credits for paid Claude plans](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans). The earlier promotion that let Fable 5 count against weekly limits ended 2026-07-19. On Max, Fable may use "up to 50% of your weekly usage limits" and uses limits "faster than other Claude models." — [Claude Fable models on your plan](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan). Claude Code shows "Requires usage credits" on the Fable row and asks for consent before billing credits — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Fast mode on Pro = credits only:** "For Claude Code users on subscription plans (Pro/Max/Team/Enterprise), fast mode is available via usage credits only and not included in the subscription rate limits." — [Fast mode](https://code.claude.com/docs/en/fast-mode)
- **1M-context legacy variants:** on Pro, "Opus 4.6 with 1M context" and "Sonnet 4.6 with 1M context" each "Requires usage credits". Current models (Opus 4.7+, Sonnet 5+, Haiku 5.5, Fable) run the 1M window natively. — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Switching models does not help with a session or weekly limit:** these are "a seat-based usage window on a subscription plan, shared across all models, so the developer can't restore access by switching models with `/model`." Switching model family does help only after a model-specific "You've hit your Opus limit" or "Sonnet limit" message. On v2.1.234+, Claude Code can "wait and continue the interrupted task automatically after the reset" (`/rate-limit-options`). — [Manage costs effectively](https://code.claude.com/docs/en/costs); [Commands](https://code.claude.com/docs/en/commands)
- **Why usage climbs in a long session (official list):** (1) long context: "Claude Code sends your full conversation with every request, and each time Claude uses tools it sends another request carrying that batch of tool results … a one-line question in a session that has been open all day still draws usage for the whole conversation"; (2) cache misses after a break longer than the cache lifetime; (3) scheduled tasks firing while idle; (4) cross-session messages waking an idle session; (5) goal check-ins; (6) subagents and workflows; (7) agent teammates; (8) compaction itself ("`/compact` reads the conversation it summarizes … `/clear` costs nothing"). — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Opus uses quota faster:** Opus "uses meaningfully more of your quota, so consider switching to Sonnet for routine work". - **The Pro default model is now Opus 5.5:** "`default` … Pro, Max, Team, Enterprise, and Anthropic API: defaults to Opus 5.5." "Before v2.1.280, `default` resolved to Sonnet 5 on Pro and Team Standard." — [Model configuration](https://code.claude.com/docs/en/model-config)
- **2026 weekly-limit changes:** the official ClaudeDevs account posted (≈2026-08-29): "Starting September 14, we're permanently raising standard weekly limits in Claude Code by 25% for Pro, Max, Team, and seat-based Enterprise plans. Until then, the current 50% increase will be in place." — [ClaudeDevs on X](https://x.com/ClaudeDevs/status/2093742321473065266). **[3rd-party]** Commentators note that compared with the temporary +50% boost (May 13 to Sep 13, 2026) this is a net ~17% cut (index 100 → 150 → 125) — [MindStudio](https://www.mindstudio.ai/blog/claude-code-weekly-rate-limit-changes); [SmartScope](https://smartscope.blog/en/blog/claude-code-weekly-limit-september-2026/); [Vaibhav Sisinty on X](https://x.com/VaibhavSisinty/status/2093783759917404617)
- **[3rd-party][unverified]** A search summary of a FinOps site claims that on a Max 20x week "96% of tokens are cache reads", measured from Claude Code logs — [finopsllm.com](https://finopsllm.com/research/claude-pro-max-tokens-limit) (page could not be opened)
- **No published token allowance:** **[3rd-party]** "Anthropic publishes no token count for Pro or any other plan … only multipliers" (Max 5x and 20x relative to Pro) — summarized from [morphllm](https://www.morphllm.com/claude-code-usage-limits) and similar sites.

### Inferences
- For a heavy Claude Code user on Pro, the binding constraint is usually the **weekly** cap, because the 5-hour windows reset several times a week. Habits that cut tokens per task (context size, model, cache) matter more than timing tricks.
- A Pro user who never changed the model is now on **Opus 5.5 by default** (since v2.1.280). Moving routine work to Sonnet 5.5 is the single largest model lever (see section 5).
- The energy bar in the user's game should be **account-wide**, not per guild. Every guild (session), claude.ai chats and the Desktop app drain the same 5h/7d pool. Per-guild bars can only show each guild's *share* of that drain.
- If usage credits are turned on, Claude Code silently keeps working after the limit, and fast mode and Fable become possible. Setting a low monthly spend cap is the safe default for a user who wants to stay within US$20.

### Gaps
- Anthropic does not publish the Pro allowance in tokens, or how Opus, Sonnet and Haiku tokens are weighted against plan limits. The API price ratios used here are a proxy, not an official weighting.
- One secondary source claims a separate 5-hour-limit increase on 2026-09-22 tied to the Opus 5.5 launch. This could not be verified.
- A search summary said Anthropic would remove the separate Fable weekly limit when the Sep 14 change went live. The Help Center (updated this week) still describes a separate Fable weekly limit on Max. These conflict. It is irrelevant on Pro, where Fable is credits-only.
- The "limit reset" feature mentioned in the Pro article was not researched (how resets are granted).

## 2. What does the official "Manage costs effectively" page recommend, including the agent-team token costs section?

### Takeaway
The official page (code.claude.com/docs/en/costs, read 2026-10-12) recommends a short list of habits. Keep context small (`/clear` between tasks, `/compact` with instructions). Match the model to the job (Sonnet by default, Haiku for simple subagents). Cut MCP overhead (tool search, CLI over MCP, disable unused servers). Use code-intelligence plugins. Preprocess output with hooks and skills. Move instructions from CLAUDE.md into skills. Tune effort. Delegate verbose operations to subagents. Keep agent teams small (~7x tokens). Write specific prompts, use plan mode, course-correct early, and avoid idle drains.

### Cited Findings
- "Token costs scale with context size: the more context Claude processes, the more tokens you use." Claude Code optimizes automatically through prompt caching and auto-compaction. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Clear between tasks:** "Use `/clear` to start fresh when switching to unrelated work. Stale context wastes tokens on every subsequent message. Use `/rename` before clearing … then `/resume`." — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Custom compaction:** `/compact Focus on code samples and API usage`. You can also add a `# Compact instructions` section to CLAUDE.md. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Model:** "Sonnet handles most coding tasks well and costs less than Opus. Reserve Opus for complex architectural decisions or multi-step reasoning … A switch to Opus also applies to the subagents that inherit your session's model. For simple subagent tasks, specify `model: haiku`." — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **MCP:** definitions are "deferred by default … only tool names and server instructions enter context". "Prefer CLI tools when available: Tools like `gh`, `aws`, `gcloud`, and `sentry-cli` are still more context-efficient than MCP servers because they don't add any per-tool listing." "Disable unused servers: Run `/mcp`." — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Code intelligence plugins:** "A single 'go to definition' call replaces what might otherwise be a grep followed by reading multiple candidate files." — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Hooks preprocessing (quantified):** "Instead of Claude reading a 10,000-line log file to find errors, a hook can grep for `ERROR` and return only matching lines, reducing context from tens of thousands of tokens to hundreds." The page gives a ready PreToolUse hook (`~/.claude/hooks/filter-test-output.sh`) that rewrites `npm test|pytest|go test` into `… 2>&1 | grep -A 5 -E '(FAIL|ERROR|error:)' | head -100`. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **CLAUDE.md to skills:** "Skills load on-demand only when invoked … Aim to keep CLAUDE.md under 200 lines by including only essentials." — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Thinking and effort:** "Thinking tokens are billed as output tokens, and the default budget can be tens of thousands of tokens per request." Lower effort with `/effort`. "You can't turn off thinking on Opus 5.5, Sonnet 5.5, Haiku 5.5, or the Fable models." `MAX_THINKING_TOKENS=8000` works only on fixed-budget models. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Subagents:** "Delegate verbose operations to subagents … only a summary returns to your main conversation. The subagent's own requests still draw on your usage" → choose a smaller model, or run every subagent on one model. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Agent-team token costs (official section):** "Use Sonnet for teammates. … Keep teams small. Each teammate runs its own context window, so token usage is roughly proportional to team size. Keep spawn prompts focused. … Shut down teammates when their work is done. … Agent teams are disabled by default (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`)." And: "**Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode**." — [Manage costs effectively](https://code.claude.com/docs/en/costs). The agent-teams page adds: "Start with 3-5 teammates … Having 5-6 tasks per teammate"; "For routine tasks, a single session is more cost-effective." — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- **Prompts and workflow:** "Vague requests like 'improve this codebase' trigger broad scanning." Use plan mode (Shift+Tab), press Escape to course-correct, use `/rewind` or double-Esc, give verification targets, and test incrementally. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Background usage:** resume summarization and similar jobs cost "typically under $0.04 per session". Prompt suggestions are "mostly cache reads plus a few output tokens", are skipped near the usage limit, and can be turned off. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Enterprise baseline for scale:** "the average cost is around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users" (API list-price equivalent). — [Manage costs effectively](https://code.claude.com/docs/en/costs)

### Inferences
- An average enterprise developer spends ~US$150-250/month in API-equivalent terms, roughly 7-12x the US$20 Pro price. A daily heavy Claude Code user on Pro should therefore expect to hit weekly limits unless they economize hard. Pro's included allowance is not published, so this is directional only.

### Gaps
- The official page gives few numbers: only the hook example ("tens of thousands → hundreds"), the ~7x for agent teams, and the background "<$0.04/session". No official savings percentages exist for `/clear`, model choice or CLAUDE.md trimming.

## 3. Prompt caching in Claude Code: TTLs, what breaks the cache, and how to keep hit rates high

### Takeaway
Claude Code caches automatically by exact **prefix match**. The layers are system prompt + tools, then CLAUDE.md/memory, then the conversation. On a Pro subscription within plan usage, the **main conversation gets a 1-hour TTL**. Subagents, workflows, teammates, forks and compaction get **5 minutes**. If you go over the limit onto usage credits, the main conversation also drops to 5 minutes. A cache read on Opus/Sonnet 5.5 costs **0.05x** the input price. A miss that rewrites the cache costs 1.25x (5m) or 2x (1h). So a miss on a large context costs roughly **25-40x** a hit for the input part. The cache breaks on: model switches, effort changes on older models, turning fast mode on, MCP/plugin tool-set changes (unless tools are deferred), bare-tool deny rules without tool search, compaction, image eviction, upgrades, and idle periods longer than the TTL.

### Cited Findings
- **Mechanism:** "The API caches by matching the start of each request … The match is exact, so a change anywhere in the prefix recomputes everything after it. There is no per-file or per-segment caching." — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Layer order:** system prompt (core instructions, tool definitions) → project context (CLAUDE.md, auto memory, unscoped rules) → conversation. "A change to the system prompt invalidates everything." Plan mode and skill loading append messages, so the cached prefix stays intact. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Official tip:** "Pick your model and effort level at the top of a session, then save `/compact` for natural breaks between tasks. The fewer changes you make mid-task, the higher your cache hit rate." — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **TTL buckets:** on a subscription within plan usage, "Main conversation: One hour"; "Everything else" (subagents, workflows, in-process teammates, forks, compaction, session titles): "Five minutes, except the server-controlled helper requests". With usage credits, API key or a cloud provider, both buckets get five minutes. "Once you go over your plan's usage limit and Claude Code draws on usage credits … Claude Code drops the main conversation to the five-minute TTL." — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Choosing the TTL yourself (v2.1.242+):** main conversation: `promptCacheTtl` setting or `CLAUDE_CODE_PROMPT_CACHE_TTL`. Everything else: `subagentPromptCacheTtl` or `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`. Values are `5m` or `1h`. Precedence: `FORCE_PROMPT_CACHING_5M=1` > bucket env var > bucket setting > subagent frontmatter `experimental.cacheTtl` (v2.1.248+; a `1h` there is ignored while the subscription is on usage credits) > `ENABLE_PROMPT_CACHING_1H=1` > default. To verify, run `claude -p "hello" --output-format json` and check `usage.cache_creation.ephemeral_1h_input_tokens` and `ephemeral_5m_input_tokens`. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **TTL trade-off:** the 1-hour TTL "charges a higher rate for cache writes … It costs more on short bursts of work that never idle past five minutes." — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Prices (API, read 2026-10-12):** Opus 5.5 costs $4 base input, $5 for 5m writes, $8 for 1h writes, $0.20 for cache hits and $20 output per MTok. Sonnet 5.5: $2 / $2.50 / $4 / $0.10 / $10. Haiku 5.5 (prompts ≤100K tokens): $0.10 / $0.125 / $0.20 / $0.01 / $0.50; above 100K: $0.50 / $0.625 / $1 / $0.05 / $2.50. Fable 5.1: $10 / $12.50 / $20 / $0.25 / $50. Multipliers: a 5m write is 1.25x base input and a 1h write is 2x. A cache read is 0.1x, except "0.025x on Claude Fable 5.1 … 0.05x on Claude Opus 5.5 and Claude Sonnet 5.5". — [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- **Actions that invalidate the cache (official list):** switching models; changing effort level; turning on fast mode; connecting or removing an MCP server; enabling or disabling a plugin; denying an entire tool; compacting; accumulating many images; upgrading Claude Code. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
  - **Model switch:** "Each model has its own cache." `/model` asks for confirmation while the cache is warm. **`opusplan` makes "each plan-mode toggle … a model switch"**, and a skill whose frontmatter names another `model` is a model switch for that turn. Automatic model fallback on Fable, Opus 5.5 and Sonnet 5.5 is also a switch.
  - **Effort:** this breaks the cache on most models. However, "On Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable 5.1 with an API key or a Claude subscription, changing effort keeps the cache."
  - **Fast mode:** the first request with fast mode on re-reads the whole history uncached, billed at fast-mode rates. The cost applies once per conversation, so turn it on at the start, not deep into a session.
  - **MCP:** with tool search (the default), "Claude Code keeps the tool list from the conversation's first request for the whole conversation", so mid-session server changes don't disturb the cache. Without tool search, a server connecting or being removed on purpose invalidates it. "Editing your MCP config does not by itself change the cache" (it applies on restart).
  - **Plugins:** skills, commands, agents, hooks, monitors and themes never invalidate. Plugin MCP servers follow the MCP rules. `/reload-plugins` warns and holds a reload that would force a full re-read.
  - **Images:** when the image/PDF limit is reached, the oldest are dropped in batches, causing one slower turn per batch.
  - **Upgrades:** the first conversation after an upgrade rebuilds the cache. `DISABLE_AUTOUPDATER=1` lets you control when upgrades apply.
- **Actions that keep the cache:** editing repository files; editing CLAUDE.md mid-session ("does not invalidate the cache, but the edit also doesn't apply" until `/clear`, `/compact` or restart); changing permission mode (except under `opusplan`); changing output style (v2.1.251+); invoking skills and commands; `/recap`; `/rewind` ("truncates back to a prefix that is already cached"); spawning a subagent. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Compaction cost:** while the cache is warm, the summarization request reads the prefix from cache, "so a mid-session `/compact` costs a fraction of what the context size suggests". "After a break longer than the cache lifetime … the summarization request reprocesses the full history as uncached input. This is why `/compact` costs the most when you resume an old session." Tip: compact "at a natural break … instead of waiting for auto-compaction"; to abandon a path, use `/rewind` instead. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Cache scope:** "effectively scoped to one machine and directory … Two sessions in different directories therefore build different prefixes and miss each other's cache. Sessions you run in parallel in the same directory … read each other's cache." — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Subagents and forks:** a subagent "doesn't read the parent's cache … it warms a cache of its own" with a 5-minute TTL even on a subscription. "A fork … inherits the parent's system prompt, tools, and conversation history exactly, so its first request reads the parent's cache." Resumed subagents can read the cache the original run warmed. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching); [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Resume from a summary:** "On a Pro or Max plan, when you resume a session that has been inactive for more than about an hour and is over 100,000 tokens", Claude Code offers *Resume from summary* (runs `/compact`), *Resume full session as-is*, or *Don't ask me again*. — [Sessions](https://code.claude.com/docs/en/sessions)
- **Checking it:** `/usage` → `Prompt cache (main)` line (v2.1.251+) shows requests, the share of input from cache, misses with a "likely cause" (v2.1.260+), expected rebuilds, and "warm (1h TTL …)" or cold. In the status line, read `current_usage.cache_creation_input_tokens` vs `cache_read_input_tokens` ("A high read-to-creation ratio means caching is working well"). — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching); [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Design rationale:** the docs link a blog post, "Lessons from building Claude Code: Prompt caching is everything", for "the design rationale for plan mode, deferred tool loading, and compaction". — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching) (the post redirects to claude.dev, which could not be reached from this environment)

### Inferences
- **A miss vs a hit, quantified from list prices:** a 200K-token context on Opus 5.5 (the Pro default) costs about $0.04 of input per request on a hit (200K × $0.20/MTok). On a miss with a 1h rewrite it costs about $1.60 (200K × $8/MTok), which is **~40x**. With a 5m rewrite it is ~$1.00, or **~25x**. Sonnet 5.5: $0.02 vs $0.80. This is the main reason to (a) choose model and effort at the start, (b) avoid toggling MCP servers or plugins mid-task, (c) come back to a session within an hour or accept "Resume from summary", and (d) be careful with `opusplan`, since each plan↔execute toggle is a cache rebuild.
- **Conflict worth noting:** the Help Center recommends `/model opusplan` ("plan with Opus, execute with Sonnet") — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code). The prompt-caching page warns that each plan-mode toggle under `opusplan` starts a fresh cache. Net advice: plan once per task in Opus, then stay in execution. Don't flip back and forth.
- **Effort is now cheap to change** on the 5.5 models, because it keeps the cache. Raise or lower effort per step instead of switching models.
- On Pro, the default 5-minute TTL for subagents is fine when a subagent works continuously. Set `subagentPromptCacheTtl: "1h"` (or per-agent `experimental.cacheTtl`) only for long-lived agents that are resumed after gaps of 5-60 minutes, because 1h writes cost 2x instead of 1.25x.
- Each guild in the game is one folder, which means one cache scope. Two parallel sessions in the *same* folder share a cache, but guilds in different folders never do.

### Gaps
- The claude.dev blog "Prompt caching is everything" could not be fetched, so its internal cache-hit statistics (if any) are missing.
- How cache reads are weighted against *subscription* limits (as opposed to API dollars) is not published.

## 4. Context management: /clear, /compact, auto-compact thresholds, /context, CLAUDE.md size, skills vs always-on instructions, MCP overhead and tool search

### Takeaway
Context is the main cost multiplier. Use `/clear` between unrelated tasks (free). Use `/compact <focus>` at natural breaks while the cache is warm. **Lower the auto-compact window.** Current 1M-native models, including Pro's default Opus 5.5, only auto-compact at **~967K tokens** by default, and every request re-reads the whole context. Keep CLAUDE.md under 200 lines (imports don't help). Move procedures into skills, which load on demand. Rely on MCP tool search (default) and prefer CLI tools. Use `/context`, `/doctor` and `/skill-doctor` to see what fills context.

### Cited Findings
- **The core constraint:** "Claude's context window fills up fast, and performance degrades as it fills." "If you've corrected Claude more than twice on the same issue in one session … Run `/clear` and start fresh with a more specific prompt." Anti-patterns are named: the "kitchen sink session" and the "infinite exploration". — [Best practices](https://code.claude.com/docs/en/best-practices)
- **`/clear` is "the single most effective lever for both quality and cost".** Test: "if your next prompt would make perfect sense in a brand-new terminal, clear before sending it." Warning: "/clear cannot be undone." — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)
- **Auto-compact defaults:** "Models running with a native 1M window compact before the window fills, at about 967K tokens by default. These include the Fable models, Sonnet 5 and later, Haiku 5.5, and Opus 4.7 and later." Sonnet 4.6 and Opus 4.6 without extended context compact at 200K. — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Setting it lower:** `/autocompact 500k` saves per model in `modelSettings`, and `/autocompact auto` resets it. `autoCompactWindow` (e.g., `200000`) in settings applies to every model, and `--autocompact` applies to one launch. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (plain integer, 100000-1000000) overrides all of these. The range is 100K to 1M. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (1-100, can only lower the threshold) also applies to subagents. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` holds models at 200K. — [Model configuration](https://code.claude.com/docs/en/model-config); [Environment variables](https://code.claude.com/docs/en/env-vars)
- **What survives compaction:** the system prompt and output style; root CLAUDE.md, unscoped rules and auto memory are re-injected from disk; the plan is re-injected; up to **5** recently modified files are re-read (files over 5,000 tokens come back as a reference only); invoked skill bodies are re-injected "capped at 5,000 tokens per skill and 25,000 tokens total"; path-scoped rules and nested CLAUDE.md are reloaded on demand; SessionStart hooks with the `compact` source can add context. — [Explore the context window](https://code.claude.com/docs/en/context-window)
- **Other context tools:** `/compact focus on …`; `/rewind` → "Summarize from here / up to here"; `/autocompact`; `/clear`; delegate large reads to subagents; `/context` for "a live breakdown by category with optimization suggestions, including which CLAUDE.md and auto memory files loaded". — [Explore the context window](https://code.claude.com/docs/en/context-window)
- **CLAUDE.md size:** "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." "Imports help you organize a long file but don't reduce its context cost, because imported files also load at launch." "Block-level HTML comments (`<!-- maintainer notes -->`) in CLAUDE.md files are stripped before the content is injected", so they cost no tokens. Auto memory `MEMORY.md`: "first 200 lines … or the first 25KB" are loaded. Path-scoped rules load only with matching files. You get a startup and `/status` warning when files exceed the recommended length. — [Memory](https://code.claude.com/docs/en/memory)
- **"Two strikes" rule:** "Only add a note the second time you have to correct Claude on the same thing … Keep the file under roughly 200 lines." "This file is prepended to every turn. Prompt caching means turns after the first are billed at the much cheaper cache-read rate … but it still occupies context-window space on every message." — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)
- **Skills = progressive loading:** "a skill's body loads only when it's used, so long reference material costs almost nothing until you need it." Only names and descriptions sit in context. "The combined `description` and `when_to_use` text is truncated at 1,536 characters". The listing budget "scales at 1% of the model's context window". `disable-model-invocation: true` gives "Description not in context, full skill loads when invoked". `/doctor` estimates listing cost and `/skill-doctor` (v2.1.252+) "Show[s] what each of your skills costs in context and how often it gets used". Supporting files in a skill directory load only when needed. — [Skills](https://code.claude.com/docs/en/skills); [Commands](https://code.claude.com/docs/en/commands)
- **MCP tool search:** "Tool search keeps MCP context usage low by deferring tool definitions until Claude needs them. Only tool names and server instructions load at session start." It is on by default for Sonnet/Haiku/Opus 4.5 and later, and off when `ANTHROPIC_BASE_URL` points at a non-first-party host. `ENABLE_TOOL_SEARCH=auto` loads upfront when definitions take less than 10% of context (`auto:5` sets 5%), and `false` loads everything upfront. `alwaysLoad: true` per server should be used "for a small number of tools that Claude needs on every turn". — [MCP](https://code.claude.com/docs/en/mcp)
- **MCP output limits:** there is a warning when tool output exceeds **10,000 tokens** and a default cap of **25,000 tokens** (`MAX_MCP_OUTPUT_TOKENS`). Text results over 50,000 characters are saved to a file. — [MCP](https://code.claude.com/docs/en/mcp)
- **Help Center for chat:** "Turn off tools you don't need … Tools and connectors are token-intensive." — [How do usage and length limits work?](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)
- **[3rd-party][unverified]** Systima's measurement, via search summary: Claude Code used "about 33,000 tokens before processing user input, rising to about 75,000 in a practical setup with MCP servers and instruction files"; each small MCP server added ~1,000-1,400 tokens; "a 72KB instruction file added approximately 20,000 tokens per request". An "MCP token budget autopsy" reported 50,000-67,000 tokens before the first prompt with 5-10 servers before tool search, cut "to 8.5K with one configuration change". — reported via [getunblocked.com autopsy](https://getunblocked.com/blog/mcp-token-budget-autopsy/) and [aident.ai](https://aident.ai/blog/reduce-mcp-token-usage-claude-code-codex). The pages could not be opened. Pre-tool-search figures are likely outdated for current versions.
- **Context-engineering principles (Anthropic Engineering, 2025-09-29):** "context rot": recall degrades as context grows. Aim for "the smallest possible set of high-signal tokens". Use just-in-time retrieval (keep file paths and identifiers, load at runtime). Compaction keeps a summary plus "the five most recently accessed files". Tool-result clearing is the "lightest-touch" compaction. Use structured note-taking (NOTES.md, to-do lists). — [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### Inferences
- **Long-context drag, quantified from list prices:** cache reads are cheap per token but are paid on **every request**, and a turn with N tool calls makes about N+1 requests. On Opus 5.5 at 800K context, re-reading costs ~$0.16 per request, so a 15-tool-call turn costs ~$2.56 before output. At 100K the same turn costs ~$0.32. Capping context with `/autocompact 200k` and clearing between tasks therefore cuts per-turn input cost several-fold in long sessions. API-dollar proxy; plan weighting is unpublished.
- The ~967K default threshold is generous for quality and expensive for usage. A Pro user should set `/autocompact` to 150-250K, or set `"autoCompactWindow": 200000` in `~/.claude/settings.json`, so sessions never balloon. Trade-off: more frequent compactions, each a large request, and lost detail. `/clear` plus a handoff file is cheaper when continuity isn't needed.
- Haiku 5.5 costs 5x more per token above 100K-token prompts. For Haiku agents (cheap NPCs), keeping context under 100K keeps them in the cheap tier.

### Gaps
- No official per-component token numbers (system prompt, tool list) for the current version; `/context` in the user's own session is the authoritative check.
- Whether a per-model `/autocompact` value saved for Haiku also governs Haiku *subagents* is not documented. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is documented to apply to subagents.

## 5. Model routing: relative cost of Haiku/Sonnet/Opus/Fable, per-subagent models, CLAUDE_CODE_SUBAGENT_MODEL, effort levels, fast mode, and when Opus is worth it

### Takeaway
At list prices (Oct 2026), **Opus 5.5 costs 2x Sonnet 5.5 per token, and Haiku 5.5 costs 1/20th of Sonnet 5.5** (for prompts ≤100K). Fable 5.1 is 2.5x Opus 5.5 and is credits-only on Pro. Since v2.1.280, Pro defaults to Opus 5.5 at **medium** effort. Explore subagents inherit the main model. Route routine work to Sonnet, mechanical subagents to Haiku (`model: haiku`, or `CLAUDE_CODE_SUBAGENT_MODEL=haiku` + `_FORCE=1`), and keep Opus for hard or ambiguous problems or a one-time plan. Effort controls how much work Claude does, not just thinking (an illustrative ~7x token gap between levels). Fast mode is never a saving on Pro (credits only, 2x price).

### Cited Findings
- **Aliases on the Anthropic API:** `opus` → Opus 5.5, `sonnet` → Sonnet 5.5, `haiku` → Haiku 5.5, `fable` → Fable 5.1, and `best` → Fable where available, otherwise Opus. Version needs: Sonnet 5.5 v2.1.284+, Opus 5.5 v2.1.280+, Haiku 5.5 v2.1.293+. — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Prices:** see section 3 (Opus 5.5 $4/$20; Sonnet 5.5 $2/$10; Haiku 5.5 $0.10/$0.50 ≤100K and $0.50/$2.50 above; Fable 5.1 $10/$50 per MTok input/output). — [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- **Choosing a model:** "Sonnet for most coding (features, tests, known bugs, refactors); Opus when you're genuinely stuck or the change is wide (hard debugging, cross-cutting refactors, architecture calls); Haiku for quick mechanical work (renames, log lines, regex explanations, boilerplate)." "The highest-value use of Opus is writing the plan itself." — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)
- **Official blog (Lydia Hallie, 2026-07-07):** "Effort level controls how much work Claude does on your request overall", including files read, verification and steps before checking in. A figure caption reads: "Same prompt, two effort levels. The high effort path generates roughly 7x more tokens" (illustrative). "For most tasks you should use the model's default effort level." "If Claude has all the pertinent context, clearly tried, and still got it wrong, that's a signal to pick a more capable model. If Claude got it wrong by skipping a file, not running the tests, or bailing on a refactor partway through, pick a higher effort level." On hard multi-step work, "the total cost per task can come out lower" with the larger model. "If you're on the larger model and the work has been routine for a while, dropping down will increase speed and typically reduce cost." — [Choosing a Claude model and effort level in Claude Code](https://claude.com/resources/articles/claude-model-and-effort-level-in-claude-code)
- **Effort levels:** low / medium / high / xhigh / max on the 5.5 and Fable models. Defaults: "`high` on every model that supports effort, except that Opus 5.5, Sonnet 5.5, and Haiku 5.5 default to `medium`". "`low`: Quick exchanges where you review each result … small change like a rename". "`max` may show diminishing returns and is prone to overthinking". "In Anthropic's testing, Opus 5.5 at `medium` matches or exceeds Opus 5 at `high`." Set effort with `/effort <level>` (Enter saves; `s` applies to this session only), `--effort`, `CLAUDE_CODE_EFFORT_LEVEL`, `modelSettings`, or `effort:` in skill/subagent frontmatter. `ultrathink` in a prompt gives one-off deeper reasoning; other phrases like "think hard" are not keywords. **Ultracode** makes Claude orchestrate dynamic workflows (many agents). — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Thinking:** "You can't turn thinking off on Opus 5.5, Sonnet 5.5, Haiku 5.5, or the Fable models … the model decides per step how much to think based on the effort level." "You are charged for all thinking tokens generated, even when collapsed or redacted." — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Subagent model resolution (v2.1.251+):** per-invocation `model` parameter > frontmatter `model` (`inherit` = main model) > `CLAUDE_CODE_SUBAGENT_MODEL` > main model. "If an installed mod sets a model in its `agent.spawn` hook, Claude Code uses that model in place of the per-invocation parameter." To force one model on all subagents, teammates and workflow agents: `{"env": {"CLAUDE_CODE_SUBAGENT_MODEL": "haiku", "CLAUDE_CODE_SUBAGENT_MODEL_FORCE": "1"}}` (v2.1.257+). Forks and `model: inherit` fork-skills still use the main model. Check the actual model with `/tasks`. Subagents inherit the main session's thinking setting (v2.1.198+). Per-subagent `effort` is set in frontmatter. — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Explore runs on the main model:** "Model: the main conversation's model." "A user or project subagent named `Explore` overrides the built-in and keeps its own `model` field, so define one with `model: haiku` to run exploration on a lower-cost model." Explore and Plan skip CLAUDE.md and git status "to keep research fast and inexpensive". — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Fast mode:** "up to 2.5x faster at a higher cost per token". Opus 5.5 fast costs $8/$40 per MTok, compared with $4/$20 standard. On Pro it is "available via usage credits only", and "Fast mode usage draws directly from usage credits, even if you have remaining usage on your plan." Enabling it mid-conversation bills the whole context once at the uncached fast rate. — [Fast mode](https://code.claude.com/docs/en/fast-mode); [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- **Advisor pattern:** pair a faster main model with a stronger advisor that Claude consults "at decision points rather than on every turn, so pairing a faster main model with a stronger advisor typically costs less than running the stronger model throughout". On subscriptions, "advisor usage counts toward your plan's usage limits" (a Fable advisor bills to credits). Set it with `/advisor <model>`. Toggling the advisor keeps the cached prefix. — [Advisor](https://code.claude.com/docs/en/advisor); [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Persisting the choice:** "`/model` saves your choice as the default for new sessions by writing the `model` field in your user settings … `Enter`: switch model and save as your default · `s`: switch model for this session only … Typing `/model <name>` directly behaves like `Enter`." An `ANTHROPIC_MODEL` env var is overridden on later launches by a model saved with `/model`. — [Model configuration](https://code.claude.com/docs/en/model-config)
- **`opusplan`:** Opus in plan mode, Sonnet in execution. — [Model configuration](https://code.claude.com/docs/en/model-config) (cache caveat in section 3)
- **Org-level controls also exist** (`availableModels`, `maxEffortLevel`); not relevant for an individual Pro user. — [Model configuration](https://code.claude.com/docs/en/model-config)

### Inferences
- **Relative per-token cost at list price, with Sonnet 5.5 = 1:** Haiku 5.5 ≈ 0.05 (0.25 above 100K), Opus 5.5 ≈ 2, Fable 5.1 ≈ 5 (credits-only on Pro). If plan weighting follows API prices (not published), moving the default from Opus 5.5 to Sonnet 5.5 roughly halves per-token usage. Moving mechanical subagents to Haiku 5.5 cuts their cost by ~95% vs Sonnet.
- **When Opus is worth it:** hard or ambiguous debugging, architecture, wide refactors, or after Sonnet "clearly tried and still got it wrong". There Opus may finish in fewer turns, so total cost per task can be lower. Use Opus once per task for the plan, then stay on Sonnet. Never use fast mode on Pro unless deliberately paying credits.
- On Pro, don't leave Explore on Opus. Define a project/user `Explore` agent with `model: haiku`, or force `CLAUDE_CODE_SUBAGENT_MODEL=haiku`. Accept some loss of quality on complex research subagents.
- Effort changes keep the cache on the 5.5 models and model switches don't. So "turn the dial" (effort) mid-session rather than "swap the engine" (model).

### Gaps
- No official numbers for how much of the Pro limit one Opus vs Sonnet vs Haiku turn consumes.
- The ~7x effort figure is from an illustrative diagram, not a benchmark.
- The blog's "Spending your effort" companion post (claude.dev) could not be fetched.

## 6. Subagents vs main thread vs agent teams vs forks: when each saves or wastes tokens

### Takeaway
Subagents **save main-context tokens** by isolating verbose work: tens of thousands of tokens are explored and ~1-2K come back. However, they **spend their own tokens**, start with a cold cache (5-minute TTL), and reload CLAUDE.md unless told not to. Forks share the parent's cache and are cheaper for context-heavy side tasks. Agent teams are the most expensive (~7x in plan mode). Use the main thread for iterative, shared-context work and `/btw` for quick questions about what's already in context.

### Cited Findings
- **Official decision rule.** Use the main conversation for frequent back-and-forth, phases that share significant context, quick targeted changes, or when latency matters. Use subagents for verbose output, tool restrictions, or self-contained work that returns a summary. "For a question about something already in your conversation, use `/btw` … It sees your full context but has no tool access, and the answer isn't added to history." — [Sub-agents](https://code.claude.com/docs/en/sub-agents); [Interactive mode](https://code.claude.com/docs/en/interactive-mode)
- **Isolate high-volume operations:** "Running tests, fetching documentation, or processing log files can consume significant context … the verbose output stays in the subagent's context". Warning: "Running many subagents that each return detailed results can consume significant context, and each subagent spends tokens of its own." — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **What a fresh subagent loads:** its own system prompt, the task message, every CLAUDE.md level (except for Explore/Plan, or when `omitClaudeMd: true`), git status, preloaded skills, and a sibling roster. "Delegating to a model with a smaller window gives that subagent the smaller window." — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Forks (`/subtask`, v2.1.212+; fork mode on by default in interactive sessions since v2.1.232):** "Because a fork's system prompt and tool definitions are identical to the parent, its first request reuses the parent's prompt cache … a fork costs less than a fresh subagent for tasks that need the same context." Only the fork's final result returns. — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Resume instead of re-spawn:** a resumed subagent "can keep reading the prompt cache the original run warmed". Explore/Plan are one-shot and cannot be resumed. — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Limits:** nesting defaults to 3 layers (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, set `1` to turn nesting off). Concurrency defaults to 20 running subagents (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`). Ultracode sessions are exempt. — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Agent teams:** "Higher [token cost]: each teammate is a separate Claude instance" (vs "Lower: results summarized back to main context" for subagents). ~7x more tokens in plan mode. Start with 3-5 teammates. — [Agent teams](https://code.claude.com/docs/en/agent-teams); [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Subagent return size (Anthropic Engineering, 2025-09-29):** each sub-agent "might explore extensively, using tens of thousands of tokens or more, but returns only a condensed, distilled summary of its work (often 1,000-2,000 tokens)". — [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **Usage attribution:** `/usage` on Pro shows the subagent, skill, plugin and per-MCP-server share of recent usage. — [Manage costs effectively](https://code.claude.com/docs/en/costs)

### Inferences
- A fresh subagent pays a cache *write* for its prefix (system prompt + CLAUDE.md + task). For tiny tasks (one grep, one lookup), that overhead can exceed the savings, so do these in the main thread or ask via `/btw`. Subagents pay off when the work would add more than a few thousand tokens of tool output to the main context.
- For one-off "freelancer" NPCs: use Haiku, `omitClaudeMd: true`, a tight `tools` list, `maxTurns`, low effort, and a request for a short summary.
- For side quests needing the leader's full context: use a fork, which shares the cache, not a fresh subagent.
- For "raids", avoid agent teams on Pro except for genuinely parallel, independent work.

### Gaps
- No official measurement of a fresh subagent's fixed startup overhead in tokens.

## 7. Reading files efficiently, avoiding re-reads, keeping huge tool outputs out of context, and concise outputs

### Takeaway
Point at files by path, not by pasting or `@`-mentioning. Let Claude grep and read in pages. Trim logs to the relevant lines. Filter test and build output with a hook, or run it in a subagent. Rely on the built-in output caps (Bash ~30K chars, Read 25K tokens per call, MCP 25K tokens). Code-intelligence plugins and a "codebase overview" skill prevent exploratory reads. The **Concise** output style cuts narration and recaps.

### Cited Findings
- **Paths, not pastes:** "Anything you paste sits in context, in full, for the rest of the session. Referencing a file by path lets Claude read selectively … (Note that the @ prefix injects the entire file plus its CLAUDE.md tree into context, so use a bare path when you are trying to save tokens.) For logs and stack traces, trim to the relevant 20 or 30 lines before pasting. For anything large (lockfiles, build logs, data dumps), put it on disk and reference the path." — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)
- **Specific prompts:** "Specific requests like 'add input validation to the login function in auth.ts' let Claude work efficiently with minimal file reads." — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Read limits:** "one call returns at most 25,000 tokens … and refuses a whole file over 256 KB, so Claude reads a larger file in pages with `offset` and `limit`." On v2.1.296+, `allow_large: true` can read more when context has room. `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` changes the cap. — [Tools reference](https://code.claude.com/docs/en/tools-reference); [Environment variables](https://code.claude.com/docs/en/env-vars)
- **Bash output:** output is inline "up to roughly 30,000 characters by default; past that, the path of a file saved to the session directory … plus a preview of up to the first 2,000 characters". `BASH_MAX_OUTPUT_LENGTH` defaults to 30,000 with a maximum of 150,000. Raising it enlarges context use. — [Tools reference](https://code.claude.com/docs/en/tools-reference)
- **Re-reads:** "Editing a file Claude previously read does not retroactively change the earlier read in history. Instead, Claude Code appends a `<system-reminder>` noting the file changed, and Claude re-reads it if needed." After compaction, up to 5 recent files are re-read automatically. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching); [Explore the context window](https://code.claude.com/docs/en/context-window)
- **Hook filtering:** the official PreToolUse example (section 2) reduces "tens of thousands of tokens to hundreds". — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Skills as pre-digested knowledge:** "a 'codebase-overview' skill could describe your project's architecture … instead of spending tokens reading multiple files". — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Code intelligence (LSP) plugins:** precise symbol navigation replaces grep plus multiple file reads, and type errors are reported automatically after edits. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Concise output style (v2.1.237+):** "the first sentence of a response states what happened or what the answer is. Claude leaves out the lead-in, the step-by-step narration, and the closing recap, and answers a simple question in one to three sentences. It does the engineering work as thoroughly as in the Default style." Switching style mid-session keeps the cache (v2.1.251+). Subagents ignore the main output style (except forks). — [Output styles](https://code.claude.com/docs/en/output-styles); [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching); [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Images:** many screenshots trigger batch eviction and a cache rebuild (section 3). — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)

### Inferences
- Output tokens cost 5x input at list price, and thinking counts as output. Concise style plus lower effort for routine Q&A reduces the most expensive token class. No official percentage is published.
- In game logs and test runs, wrap commands so only failures reach the context, for example via the PreToolUse hook or a "scribe" subagent that returns a summary.

### Gaps
- No official or measured numbers for Concise vs Default output-token savings.

## 8. Monitoring: /usage, /cost, /context, the status line and ccusage — what each shows

### Takeaway
`/usage` (aliases `/cost`, `/stats`) is the main in-app monitor on Pro. It shows plan bars, attribution (skills/subagents/plugins/MCP), behavior flags at ≥10% (long context, cache misses), `/loop` costs and the prompt-cache line, but only for **this machine's** sessions. claude.ai **Settings > Usage** shows the authoritative 5h and weekly bars across all surfaces. The status line JSON exposes `rate_limits.five_hour/seven_day.used_percentage` and `resets_at` (Pro/Max only), `context_window.used_percentage` and `prompt_cache`. A mod can read the same data through `$.session.usage()`. **ccusage** (third-party) estimates historical usage from local JSONL logs, including 5-hour "blocks".

### Cited Findings
- **`/usage`:** "Show session cost, plan usage limits, and activity stats. … `/cost` and `/stats` are aliases." The Session dollar figure "isn't relevant for billing purposes" for Pro/Max. On Pro there is an attribution breakdown ("skills, subagents, plugins, and individual MCP servers, each shown as a percentage"), behavior flags ("long context or cache misses, flagged when one accounts for 10% or more of recent usage") and Loops rows (v2.1.242+). Press `d`/`w` for 24h/7d. "The figures are approximate and computed from local session history on this machine, so usage from other devices or claude.ai is not included." Totals reset on `/clear` (v2.1.211+). — [Manage costs effectively](https://code.claude.com/docs/en/costs); [Commands](https://code.claude.com/docs/en/commands)
- **Prompt cache line** (v2.1.251+): e.g. `14 requests · 91% of input tokens from cache · 2 misses … · warm (1h TTL, last activity 40s ago)`. A likely-cause hint needs v2.1.260+. It covers the main conversation only. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Spinner counter:** "a live, approximate count of the output the current turn has produced so far … What it leaves out: what Claude Code sends to the model". — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **`/context`:** "live breakdown by category with optimization suggestions". **`/doctor`**: estimates the skill listing cost. **`/skill-doctor`**: per-skill cost and frequency. **`/insights`**: HTML report of friction points; "the tokens count against your plan". — [Explore the context window](https://code.claude.com/docs/en/context-window); [Skills](https://code.claude.com/docs/en/skills); [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Status line fields:** `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` (0-100) and `*.resets_at` (epoch seconds). These are present "only for claude.ai Pro and Max subscribers … and only after the first API response". Also `context_window.used_percentage` (input tokens only), `context_window.current_usage` (`cache_creation_input_tokens` and `cache_read_input_tokens`), `exceeds_200k_tokens`, and `prompt_cache` (v2.1.251+). The current command reference describes `/status` as version/model/account/connectivity and puts plan limits under `/usage` — [Commands](https://code.claude.com/docs/en/commands).

### Inferences
- ccusage's dollar figures are API-equivalent estimates. They do not show the plan's percent-used. For Pro limits, rely on `rate_limits` (status line or mod) or claude.ai Settings > Usage. ccusage is useful to see *which projects or models* burned the week.
- Because `/usage` and ccusage see only local logs, chat use on claude.ai is invisible to them. The 5h/7d percentages, however, include everything.

### Gaps
- It is not documented which of these UIs (status line, `/usage` panels) render inside the **Claude Desktop app on Windows** for local Claude Code sessions. The mod side panel plus `$.session.usage()` is the reliable route there.

## 9. Community-measured tips (with numbers) and myths that do NOT help

### Takeaway
Hard, reproducible community numbers are scarce, and most quantified claims couldn't be opened from this environment. The strongest numbers are official (hook filtering: tens of thousands → hundreds of tokens; agent teams ~7x; subagent summaries 1-2K tokens; cache read 0.05x). Many popular "tips" are myths or outdated given 2026 Claude Code behavior.

### Cited Findings
- **[3rd-party][unverified] baseline overhead:** ~33K tokens before user input, ~75K with MCP servers and instruction files; 1,000-1,400 tokens per small MCP server; a 72KB CLAUDE.md ≈ 20K tokens per request. Pre-tool-search setups: 50-67K tokens with 5-10 servers, cut to 8.5K with one configuration change. — via [getunblocked.com](https://getunblocked.com/blog/mcp-token-budget-autopsy/), [aident.ai](https://aident.ai/blog/reduce-mcp-token-usage-claude-code-codex) (search summaries only)
- **[3rd-party][unverified]** "96% of tokens are cache reads" in a measured Max 20x week. — [finopsllm.com](https://finopsllm.com/research/claude-pro-max-tokens-limit) (search summary only)
- **[3rd-party]** "/compact and /clear are the two most underused ways to save usage in Claude Code" (opinion). — via [morphllm](https://www.morphllm.com/claude-code-usage-limits) / [promptslove](https://promptslove.com/blog/claude-usage-limits/) (search summary)
- **Myth 1: "Hit the limit? Switch to Haiku/Sonnet."** False for session and weekly limits, which are shared across all models. It only helps after a model-specific "Opus/Sonnet limit" message. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Myth 2: "Split CLAUDE.md into @imports to save tokens."** Imports "don't reduce its context cost, because imported files also load at launch." — [Memory](https://code.claude.com/docs/en/memory)
- **Myth 3: "Editing CLAUDE.md mid-session busts the cache / takes effect now."** It does neither; it applies after `/clear`, `/compact` or restart. — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Myth 4: "/compact is a free reset."** "`/compact` reads the conversation it summarizes … a large request. When you want a fresh start … `/clear` costs nothing." Compacting a cold session is the most expensive case. — [Manage costs effectively](https://code.claude.com/docs/en/costs); [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Myth 5: "Say 'think hard' / 'think less' to control spend."** Only `ultrathink` is a recognized keyword; "think", "think hard" and "think more" pass through as ordinary text. Use `/effort`. — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Myth 6: "Turn off extended thinking to save."** That is impossible on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable. `MAX_THINKING_TOKENS=0` and `alwaysThinkingEnabled:false` have no effect there. Lower the effort instead. — [Model configuration](https://code.claude.com/docs/en/model-config)
- **Myth 7: "@-mention files so Claude doesn't have to search."** `@` "injects the entire file plus its CLAUDE.md tree"; a bare path is cheaper. — [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)
- **Myth 8: "Fast mode saves usage because it finishes sooner."** On Pro it bills only to usage credits, at 2x Opus 5.5 rates, plus a one-time uncached re-read when enabled mid-session. — [Fast mode](https://code.claude.com/docs/en/fast-mode)
- **Myth 9: "More parallel agents = more done for the same budget."** Each subagent and teammate spends its own tokens. Teams use ~7x in plan mode, and many detailed subagent results bloat the main context. — [Sub-agents](https://code.claude.com/docs/en/sub-agents); [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Myth 10: "1M context means I never need to clear."** Every request re-sends the context. Quality degrades as context fills, and 1M-native models only auto-compact at ~967K. — [Best practices](https://code.claude.com/docs/en/best-practices); [Model configuration](https://code.claude.com/docs/en/model-config)
- **Myth 11 (outdated): "Every MCP server dumps all its tool schemas into context."** True before tool search. MCP tools are now deferred by default (only names and instructions load). CLI tools are still leaner. — [MCP](https://code.claude.com/docs/en/mcp); [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Myth 12: "Changing effort mid-session always breaks the cache."** It no longer does on Opus 5.5, Sonnet 5.5, Haiku 5.5 or Fable 5.1 on a subscription (it does on older models). — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- **Myth 13: "`/cost` or the Session $ figure is what Pro costs me."** It is an API-list-price estimate, "not relevant for billing purposes" on Pro. — [Manage costs effectively](https://code.claude.com/docs/en/costs)
- **Myth 14: "Idle sessions don't consume anything."** Scheduled `/loop` tasks, cross-session messages, goal check-ins and live teammates send full context while idle. Fixes: `crossSessionInbound: "hold"` and `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0`. The ordinary background cost is "<$0.04 per session". — [Manage costs effectively](https://code.claude.com/docs/en/costs)

### Inferences
- The most valuable community-style measurement a user can make is their own. Run `/context` at session start, watch the `Prompt cache (main)` hit rate, and check `/usage` behavior flags weekly.

### Gaps
- No reliable, reproducible community benchmark of "% weekly limit saved" per habit was found. Several measurement sites were unreachable here.

## 10. Synthesis requested by the objective: technique catalog (with game integration idea), and ranked "top 15 habits"

### Takeaway
Ranked by expected impact for a Pro user who often hits the weekly cap. The levers are: (1) clear and keep context small, (2) stop defaulting to Opus, (3) cap auto-compact, (4) protect the cache, (5) delegate verbose work to cheap subagents, and (6) filter output. Each maps naturally to a mechanic in the user's guild RPG mod: an energy bar, aging agents, apprentices, and cheap freelancers.

### Cited Findings
- **Mod hooks the game can use:**
  - `agent.spawn` → `next({ ...e, model })` to choose a subagent's or teammate's model, or `{ deny: reason }`. It doesn't re-run on a `SendMessage` resume.
  - `turn.step` → `next({ ...e, model })` / `next({ ...e, effort })` and per-request `result.usage`.
  - `session.measure` → after each turn and on a plan-limit change.

  - `$.model.complete({ model: 'haiku', … })`, which supports cache breakpoints, for the mod's own small LLM jobs.
  - Warning: "Text from these hooks [`prompt.section`, `prompt.context`, `skill.prompt`] that changes between requests invalidates the prompt cache."
  - [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); [Mods events](https://code.claude.com/docs/en/plugins/mods/events); [Mods API](https://code.claude.com/docs/en/plugins/mods/api)

**Ranked "Top 15 habits" (by expected impact for a Pro user hitting weekly limits; ranking is an inference from the sources above)**
1. `/clear` (after `/rename`) whenever the next prompt would make sense in a brand-new session; never run "kitchen sink" sessions.
2. Make **Sonnet** your saved default (`/model sonnet` saves it to user settings). Pro now defaults to Opus 5.5. Use Opus for the plan or a genuinely hard bug, then return to Sonnet; avoid flip-flopping under `opusplan`.
3. Cap context growth: `"autoCompactWindow": 200000` (or `/autocompact 200k`), since 1M models otherwise grow to ~967K and every request re-reads it.
4. Protect the cache: fix model and effort at session start, don't toggle MCP servers or plugins mid-task, resume within an hour, and accept "Resume from summary" for big idle sessions.
5. Push tests, logs, docs and searches into **Haiku subagents** (and override `Explore` with `model: haiku`); ask them to return only a short summary.
6. Install the official **output-filtering PreToolUse hook** (test failures only) and avoid raising `BASH_MAX_OUTPUT_LENGTH`.
7. Write **specific prompts with file paths**; never paste big files or logs (trim to 20-30 lines); use bare paths instead of `@`.
8. **Plan before multi-file changes**, press Esc early, and use `/rewind` rather than arguing; after two failed corrections, `/clear` and re-prompt.
9. Keep **CLAUDE.md under 200 lines** (two-strikes rule) and move procedures into skills; imports don't save tokens.
10. Use **effort deliberately**: `low` for mechanical work, the default `medium` otherwise; avoid `max` and ultracode on Pro (effort changes are cache-safe on the 5.5 models).
11. **Prune MCP servers, plugins and skills**; prefer CLI tools like `gh`; check `/context` and `/skill-doctor`.
12. **Avoid idle drains and agent teams**: no unnecessary `/loop`, hold cross-session messages, disable goal check-ins, shut down teammates.
13. **Compact deliberately** with a focus instruction at task boundaries while the cache is warm. For a fresh start, prefer `/clear` plus a handoff file.
14. Use **`/btw`** for quick questions and **forks (`/subtask`)** for side tasks needing the current context, instead of fresh subagents.
15. **Monitor and time your work**: show 5h/7d % and context % in the status line (or the mod panel), check `/usage` attribution and flags weekly, use ccusage `blocks` for history, enable auto-continue after reset, and if you enable usage credits set a low monthly cap (never fast mode or Fable on Pro unless you mean to pay).

**Additional design cautions for the guild mod (inferences from the docs)**
- The energy bar must be **account-wide**. All guilds plus claude.ai chat share one pool. Per-guild "energy spent" can be estimated by summing `turn.step` usage per session, weighted by API price ratios. Suggested weights relative to Sonnet 5.5 input = 1: cache_read 0.05, cache_write 1.25-2, output 5, multiplied by the model factor (Haiku ≈ 0.05, Opus ≈ 2). These are an approximation, not Anthropic's real plan weighting.
- **Never inject changing numbers** (energy, age, timers) into `prompt.section` or `prompt.context`, because that invalidates the cache on every request. Keep them in the side-panel UI. If Claude must know, append them as a conversation message, the way skills and plan mode do.
- **Don't route the leader's requests to different models per step** via `turn.step` `next({...e, model})`. Each switch rebuilds the cache. Route at spawn time (`agent.spawn`) instead.
- **Aging and retirement:** measure age as absolute `context.tokens`, because `percent` of a 1M window stays tiny. Retire at ~150-200K tokens for Sonnet/Opus leaders and under 100K for Haiku NPCs (the Haiku 5.5 price tier changes above 100K). The apprentice gets a fresh session (or `/clear`) and reads a `HANDOFF.md`. Anthropic's context-engineering guidance on "structured note-taking" (NOTES.md) supports this pattern.
- **Inter-guild messages** (`$.session.send` / SendMessage) wake an idle receiving session, which then sends its full context. Batch them, or set `crossSessionInbound: "hold"`.
- **NPC defaults** for `.claude/agents/<npc>.md`: `model: haiku`, `effort: low`, `omitClaudeMd: true` (if project rules aren't needed), a minimal `tools:` list, `maxTurns:` small, and a final instruction to "return ≤ 15 lines". Long-lived fixed subagents that are resumed after idle gaps can use `experimental: { cacheTtl: 1h }`.
- The mod's own LLM calls (`$.model.complete`, e.g. NPC flavor text) should use `haiku` with a cache breakpoint on static instructions, so they don't eat the user's energy.

### Gaps
- It is not documented whether `$.model.complete` calls made by a mod count against the subscription's plan limits (they most likely do, as requests on the user's account), or whether a mod can trigger `/clear` (no `$.session.clear` is listed; `$.session.compact` exists).
- No official per-habit savings percentages exist. The ranking above is a judgment based on official mechanisms and list-price arithmetic.
