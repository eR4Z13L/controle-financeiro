## 1. Mods (plugins of function hooks) — the platform the game runs on

### Takeaway
A mod is a plugin whose JS/TS "hooks module" runs inside Claude Code's own process, can observe/rewrite/answer ~50 events (tool calls, prompts, turns, subagent spawns, usage measurements, UI drawing) and call a rich `$` API (panes, commands, tools, agents, model calls, store/state, timers, fs, process, http, inter-session messages, /config rows). It is ON by default from Claude Code v2.1.287 (terminal) / v2.1.286 (Desktop app), draws only in the terminal and the Desktop Code tab, and is explicitly "early access" — the types file for your build is the authority. For the game, the most important pieces are `$.session.usage()` + `session.measure` (context % and 5-hour/7-day plan-limit %), `agent.spawn` (choose a cheaper model per subagent), `$.agent.list()` (who spawned whom, status), `$.agent.register`/`$.agent.spawn` (NPC agent types), `$.model.fork`/`$.model.complete` (cheap side calls), `$.session.compact`, `$.session.send`, `$.config.set`, `$.ui.open` panes and `$.state`/`$.store`.

### Cited findings

**What it is / files / lifecycle**
- A mod is a plugin whose code registers event handlers ("hooks"); minimum 3 files: `.claude-plugin/plugin.json` (manifest), `hooks/hooks.json` with `"modules": ["./register.js"]` (exactly one path), and the hooks module exporting `register(on, options)`; module may be `.js/.mjs/.cjs/.jsx/.ts/.mts/.cts/.tsx`, always an ES module; `options` = values of the manifest's `userConfig` fields with defaults filled in. — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)
- The module runs in its own environment with no DOM and no Node: no `require`, no `import()`, no `setTimeout`; everything outside goes through `$`; standard web APIs (`URL`, `TextEncoder`, `AbortController`, `crypto.subtle`) exist; JSX available with `h` as factory. — [LOCALREF](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/reference.md); [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api)
- Settings hooks (shell/HTTP/prompt hooks in settings.json) vs mods: docs call a mod's handler a "hook" and the settings-file kind a "settings hook"; settings hook events are visible to mods as `classic.<Event>` (e.g. `classic.Stop`, `classic.SessionEnd`), with `e` = the stdin JSON incl. `transcript_path`. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview); [React to events](https://code.claude.com/docs/en/plugins/mods/events)
- Comparison table (official): Mod = functions in-process, can change tool calls/prompts/commands/turns/UI and CAN draw; Settings hook = shell/HTTP/prompt on lifecycle events, cannot draw; Skill = SKILL.md instructions; MCP server = external process giving tools. A plugin can hold all of them. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)

**Versions / on-off**
- "Mods are on by default. In the terminal, use Claude Code v2.1.287 or later. The Desktop app includes its own copy of Claude Code, and mods work there from v2.1.286." Check version with `claude --version` or `/status` in a Desktop Code-tab session. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)
- `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` (early-access flag) is ignored from v2.1.287; turn mods off per mod in `/plugin` → Installed, for one session with `--safe-mode`, or everywhere with `"disableAllHooks": true` in `~/.claude/settings.json` (also stops settings hooks and custom status line). Built-in mods are not stopped by `disableAllHooks`, `--bare`, `--safe-mode`. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)
- Reference page states it is "as of v2.1.290"; the GitHub copy of the types (https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts) "can be older than the Claude Code version you have installed. When the two disagree, trust the copy Claude Code writes for your version." — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- Local DTS header: "Written by Claude Code 2.1.296 … EARLY ACCESS: this surface may change between releases without notice." TypeScript 5.4+ reads it. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)

**Where mods run (critical for Windows Desktop + cloud user)**
- Terminal `claude` (incl. editor terminals, JetBrains): hooks run + drawing shows. Desktop Code tab: hooks run + drawing shows, "except elements the elements table marks terminal-only". Desktop WSL session: NO ("plugins aren't available in WSL sessions"). VS Code extension chat panel: hooks yes, drawing no. `claude -p` / Agent SDK: hooks yes, drawing no. Remote Control from claude.ai/mobile: hooks run on your machine, drawing only in the terminal on your machine. Cloud session: hooks yes "for a plugin that reaches the cloud session", drawing NO. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)
- Installing: `/plugin install <mod> --marketplace <owner>/<repo>` "is a terminal's: a local session the desktop app starts for its Code tab answers that the command is not available there. A mod installed from a terminal at the user scope loads in that local session too, and its `ui.render` hooks draw for the `desktop` surface." — [LOCALREF](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/reference.md)
- `CLAUDE_CODE_PLUGIN_DIRS`: plugin folders to load like `--plugin-dir` for apps you can't pass flags to (Desktop, SDK); absolute paths separated by `:` — or `;` on Windows; read from the environment or the `env` block of `~/.claude/settings.json` (never project settings). `CLAUDE_CODE_PLUGIN_DIR_WATCH=1` makes long-lived non-interactive sessions (SDK, desktop) hot-reload. — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); [LOCALREF](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/reference.md)
- Panes: "A pane is a sidebar beside the transcript in a wide fullscreen terminal, or a framed region above the prompt otherwise"; several open panes get tabs. A pane opened without the user asking is placed from 144 terminal columns (110 after they've opened it once). — [Draw in the interface](https://code.claude.com/docs/en/plugins/mods/interface); [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- Desktop-vs-terminal elements: `Svg` is Desktop-only (≤131,072 chars); `Raster` (≤512×256 cells) and `Image` (PNG/RGBA ≤2 MiB, kitty graphics protocol) are terminal-only; `Pane`, `AbovePrompt`, `Spinner` and transcript sites work in both; `ToolProgress`, `TurnDuration`, `InfoNotice` are terminal-only sites. "The Desktop app has no `Raster`, so check `e.surface` and draw text there." — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); [Draw in the interface](https://code.claude.com/docs/en/plugins/mods/interface)
- `$.audio.play` uses `afplay` on macOS; "a Linux or Windows terminal, having no player, plays nothing"; `$.audio.speak` uses the platform synthesizer (`say` on macOS) and rejects when there is none. → Sound effects are a macOS-only feature for now. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)

**Trust / security**
- A mod runs with your permissions, is not sandboxed (a process a mod starts runs outside the Bash sandbox), can read env vars/settings (incl. API keys), see every prompt/tool call, rewrite prompts/tool calls, approve tool calls before you're asked, and "spend your usage: call a model on your plan or API key". It cannot change what the permission prompt shows. `claude plugin validate <dir>` lists `hooks:` and `calls:` before install. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)

**Hook mechanics**
- Hook shape `($, e, next)`; `e` is deeply frozen; `next(e)` continues the chain (other mods, then Claude Code). Observe = do work + `return next(e)`; Rewrite = `next({...e, field})`; Answer = return a result without `next`. `next.signal` (AbortSignal), `next.origin` `{plugin,tier}`, `next.budget.ms/remainingMs`, `.catch(handler)` with `next.called`/`next.error.kind` (`throw|timeout|re-entry`; `re-entry`/`cause` need v2.1.292+). — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); [React to events](https://code.claude.com/docs/en/plugins/mods/events)
- Matchers: object compared field-by-field; value, array, or RegExp (e.g. `{ tool: /^mcp__github__/ }`); `'classic.*'` and `'*'` wildcards (telemetry excluded). Registering the same event twice without a matcher fails the module load. A failing hook without `.catch` is skipped (fail-open) — guards should use `.catch(... => next.called ? next(e) : {deny:'…'})` to fail closed. — [React to events](https://code.claude.com/docs/en/plugins/mods/events)
- Order of chain: built-in guard `sec-default@builtin` + org `prependPlugins` → user-installed mods → org `appendPlugins` → other built-in mods; managed-settings `PreToolUse` hooks run before every mod; other `PreToolUse` hooks run after the last mod calls `next`. — [React to events](https://code.claude.com/docs/en/plugins/mods/events)

**Full event list (by group)** — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- Tools: `tool.call` (return `next(e)`, `{deny}`, or `{result}`), `tool.check` (after rules/PreToolUse; return `{decision: allow|ask|deny}`; `e.agentId` / `e.ceiling` need v2.1.290+), `tool.describe` (rewrite description; `isDeferred` true/false).
- Prompts: `prompt.submit` (rewrite `text`, add `context` only Claude reads, or `{drop}`), `prompt.fill`, `prompt.suggest`, `prompt.edit` (50 ms budget), `prompt.autocomplete` (`{suggestions}`), `prompt.compose` (system prompt `{sections}`), `prompt.section` (per section; `{text:null}` omits), `prompt.context` (first-message context `{blocks}`), `prompt.attachment` (reminders; `{text:null}` omits), `prompt.mention` (@-file reads; v2.1.290+), `skill.prompt`, `attribution.text`.
- Commands/config: `command.run`, `command.describe`, `config.set`, `config.describe`.
- Turns: `turn.start`, `turn.step` (async generator; per model request; `next({...e, model})` / `next({...e, effort})`), `turn.complete` (return `{text}` to show a line under the answer).
- Session: `session.start` (once per mod before first prompt; not after `/clear`, `/resume`, `/branch`), `session.end` (`reason`: clear|resume|logout|prompt_input_exit|other), `session.compact` (`{skip}`), `session.receive` (`{consumed}`), `session.send` (`{isDelivered:false, reason}`), `session.append` (every stored row), `session.attach`/`session.detach`, `session.measure` ("After each turn, and when a plan limit's percent used changes").
- Subagents: `agent.offer` (`{isOffered:false}` hides a type from Claude), `agent.spawn` (`next({...e, model})` to choose its model, or `{deny}`; `e.isTeammate` for agent-team teammates; NOT re-run when Claude resumes a subagent via `SendMessage`).
- Interface: `ui.render`, `ui.resolve`, `ui.press`, `ui.input`, `ui.select`, `ui.focus`, `ui.scroll`, `ui.close`, `ui.message`, `ui.fault` (v2.1.289+).
- Other mods: `plugin.register` (`{refuse}`), `engine.create` (add a namespace to `$`). Telemetry: `telemetry.log`/`telemetry.mark` (must filter `{to:'collector'}`). Every `$` method is also an event (e.g. `fs.read`, `model.complete`).

**`$` API namespaces** — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- `$.plugin` (name, root); `$.ui` (resolve, invalidate, open, close, panes, focus, scroll, toast, status, log, notice, ask, copy, selection, blit); `$.command` (register, run, list); `$.tool` (register, call, check, list); `$.agent` (register, spawn, list); `$.model` (complete, fork, classify); `$.prompt` (submit, read, fill, suggest, compose); `$.turn` (abort); `$.session` (messages, cwd, root, model, turns, id, repo, surfaces, usage, version, compact, send, append, authorize); `$.config` (list, set); `$.settings` (read); `$.env` (get, set); `$.fs` (read, write, list, exists, stat, ancestors); `$.store` (get, set, delete, keys); `$.state` (get, set + helpers atom/read/update/derive/memberOf); `$.clock` (now, sleep, after, every); `$.http` (fetch); `$.process` (run, spawn); `$.mcp` (call, connect); `$.audio` (play, speak); `$.telemetry` (log, mark).

**Usage / context / plan limits (key for "spend fewer tokens" and the Reaper)**
- `$.session.usage()` returns `{ startedAt, context, rateLimits, cost }`; `context` = `{ tokens, window, percent, breakdown? }`; `rateLimits` = list of `{ kind, percentUsed, resetsAt }`. — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- DTS details: `kind` is `five_hour`, `seven_day`, or a Claude gateway's `spend_limit`; `percentUsed` 0–100 with ≤1 decimal; `resetsAt` ISO 8601; `rateLimits` is "empty off a subscription or before the first reading"; `cost` = `{ usd }` "summed over every priced API response this session", same figure as `/cost` and the status line. "The plain call costs nothing"; `usage({breakdown:'full'})` "sends one token-count request per tool and memory file, as /context does", `'summary'` estimates locally. Doc example: `if ((context.percent ?? 0) >= 85) await $.session.compact()`. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `session.measure` input = same figures (without breakdown) + `changed: ('context'|'rateLimits'|'cost')[]`; `rateLimits` changes when "a window moved a whole point, appeared or left, or the account's limit status changed". Observe-only. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `turn.complete` carries `answer`, `durationMs`, `isAborted`, `turnId`, `agentId` (set for a subagent's run), `usage` (token counts + model), `reason` (`answer|aborted|refusal|error`). "Every hook sees a subagent's turn, so a hook that spawns sees its children's turns too and bounds itself." — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts); [React to events](https://code.claude.com/docs/en/plugins/mods/events)
- `turn.step` result `usage`: `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, plus `model`; runs for subagents' requests too (check `e.agentId`); `result.serverToolUses` (e.g. advisor tool calls) needs v2.1.290+. — [React to events](https://code.claude.com/docs/en/plugins/mods/events)

**Agents API (key for leader/fixed/freelancer NPCs and the org chart)**
- `agent.spawn` input (DTS `AgentSpawnInput`): `prompt`, `description`, `subagentType` (rewritable, e.g. `general-purpose`, `Explore`, a plugin's agent, `fork`), `model` (alias like `haiku` or full id; "A hook sets this to pick the subagent's model"; ignored for forks), `parentModel` (pinned), `parentAgentId` (pinned; absent from main), `permissionMode` (inherited), `background` (rewrite → `run_in_background`), `fork`, `isTeammate`, `workflow {runId, agentIndex}` (workflow agents can only be refused), `name` (SendMessage address), `cwd`. Result `{ model, agentId }` or `{ deny }`. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `$.agent.spawn({ prompt, description?, subagentType?, model?, name?, cwd? })` runs in the background, resolves once started with `{model, agentId}`; "its answer is its own `turn.complete`, carrying this `agentId`" (pattern: keep a map `got[agentId]` resolved from a `turn.complete` hook). — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `$.agent.list()` → `AgentInfo { id, teammateId?, description, type, status, parentId?, spawnedBy?, name? }`; `parentId` = "the id of the agent whose loop spawned it; absent when the main loop did"; `spawnedBy` = plugin that spawned it; status `pending|running|waiting|idle|completed|failed|killed` (`idle`/`waiting` need v2.1.289+); a workflow's agents are not listed. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts); [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- `$.agent.register(spec)` defines type `<plugin>:<name>` usable from the next turn; `AgentSpec` fields = everything an agent file accepts: `name`, `description`, `prompt` (replaces session system prompt), `tools`, `disallowedTools`, `model` (`haiku|sonnet|opus`, id, or `inherit`), `effort` (`low|medium|high|xhigh|max` or integer), `permissionMode` (`default|acceptEdits|plan|auto|dontAsk|bypassPermissions`), `mcpServers`, `hooks`, `maxTurns`, `autoCompactWindow` (100,000–1,000,000 tokens; only lowers), `skills` (preloaded), `initialPrompt` (`{{intent}}` placeholder), `memory` (`user|project|local`), `background`, `omitClaudeMd` ("context carries no CLAUDE.md block"), `isolation` (`worktree|remote`). A plugin's `agents/*.md` files declare types too. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts); [LOCALREF](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/reference.md)
- `$.session.messages({ agentId })` returns a subagent's/teammate's transcript (newest 4,096 entries) — lets the Reaper read an NPC's history. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)

**Model calls (cheap side work)**
- `$.model.complete({ model, prompt, system?, maxTokens, effort, timeoutMs })`: no history/tools/CLAUDE.md; bills to the user's plan/API key; `maxTokens` default 1024, max 64,000; never rejects on API failure — check `r.isAnswered`/`r.reason`. — [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api); [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)
- Prompt caching in `$.model.complete`: pass `prompt` as blocks with `cache: true` on the last static block (v2.1.292+); TTL 5 min from settings (`subagentPromptCacheTtl: "1h"` for one hour); ≤4 breakpoints; put static text in `prompt` (not `system`) when the mod may run on Bedrock/Vertex/Foundry/gateways. — [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api)
- `$.model.fork({ prompt })` = one tool-less question over the session's own transcript with the same model/system prompt "so the API serves that prefix from its prompt cache" (`nothing-to-fork` before first response / after /clear). `$.model.classify(text, labels, {model})` defaults to "the engine's small fast model". — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)

**Commands, tools, config, prompts, messaging, compaction**
- `$.command.register({ name, description, argumentHint, immediate })` + `command.run` hook returning `{text}` (Claude reads it) or `{}` (prints nothing); `immediate: true` runs mid-turn; built-in names refused (throws). `$.command.run({ command: "status" })` runs any slash command "as if the person typed" it, queued until idle. — [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api); [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `$.tool.register({ name, description, inputSchema, isDeferred })` → model sees `mcp__<plugin>__<name>`, served by a `tool.call` hook; deferred behind ToolSearch by default; `isDeferred: false` loads it upfront (v2.1.293+). Tool description reaches the model up to 4,096 chars (16,384 once loaded via tool search). — [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api); [LOCALREF](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/reference.md)
- `$.config.list()` / `$.config.set({ key, value })` change `/config` rows "as if the person did in the menu" (keys like `theme`, `verbose`, `autoCompact`, or `<plugin>.<field>`); refused when managed settings lock the row. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `$.prompt.submit({ text, asUser? })` queues a new turn when the session is idle (Claude reads it after a sentence naming the mod unless `asUser: true`); `$.prompt.fill/suggest/read/compose`. `$.turn.abort({turnId})`. — [Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `$.session.compact({ instructions })` = same as `/compact` (trigger `plugin`), rejects while a turn runs; `session.compact` hooks can `{skip}`. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- `$.session.send({ to: {sessionId} | {agentId} | address, text })` = same delivery as the SendMessage tool, resolves `{isDelivered}`; `session.receive` origins include `peer`, `peer-send-message`, `task-notification`, `scheduled-trigger`; "The sender's name on a received message is whatever the sender wrote, so don't base a decision on it." — [Use the mods API](https://code.claude.com/docs/en/plugins/mods/api)
- `$.session.append({ message: {type:'user'|'system', content} , agentId? })` really appends a row (user row = model reads it, isMeta; system = notice the model never reads). — [LOCALREF](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/reference.md)

**UI + state**

- Cloud sessions (claude.ai/code): the game's hooks may run but nothing is drawn — the game UI cannot appear there; design a text fallback (`$.ui.log` / command text).

- No official statement about `$.audio.speak` on Windows beyond "rejects when there is no synthesizer".

## 2. CLAUDE.md, rules, imports, auto memory (/init, /memory)

### Takeaway
CLAUDE.md files are concatenated (not overridden) from managed → user → project ancestors → local, load at launch (subfolder files load on demand), are delivered as a user message after the system prompt (context, not enforcement), and should stay under ~200 lines each; imports with `@path` organize but do NOT reduce cost. Path-scoped `.claude/rules/*.md` and skills are the token-saving alternatives. Auto memory (`~/.claude/projects/<project>/memory/MEMORY.md`, first 200 lines/25 KB loaded every session) is on by default locally and is NOT loaded into subagents (they have their own `memory` field).

### Cited findings
- Locations and load order (broadest → most specific): Managed policy (macOS `/Library/Application Support/ClaudeCode/CLAUDE.md`; Linux/WSL `/etc/claude-code/CLAUDE.md`; **Windows `C:\Program Files\ClaudeCode\CLAUDE.md`**) → User `~/.claude/CLAUDE.md` → Project `./CLAUDE.md` or `./.claude/CLAUDE.md` → Local `./CLAUDE.local.md` (gitignore it). Files in ancestor dirs load at launch; files in subdirectories load once Claude reads/writes/edits a file there. All are concatenated, root → cwd, `CLAUDE.local.md` after `CLAUDE.md` at each level. — [Memory](https://code.claude.com/docs/en/memory)
- Size: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence"; imports "help you organize a long file but don't reduce its context cost, because imported files also load at launch"; a CLAUDE.md up to 4 MiB loads in full, larger is skipped; startup and `/status` warn when a file is over the recommended length or files add up past a combined limit. — [Memory](https://code.claude.com/docs/en/memory)
- Block-level HTML comments `<!-- … -->` are stripped before injection → "leave notes for human maintainers without spending context tokens". — [Memory](https://code.claude.com/docs/en/memory)
- Imports: `@path/to/file` (relative to the importing file, absolute, or `@~/…`), max depth 4 hops; spaces escaped with backslash (`@Design\ Docs/x.md`); code spans/fences are not parsed; external imports in project files trigger a one-time approval dialog. — [Memory](https://code.claude.com/docs/en/memory)
- `/init` generates a starter CLAUDE.md (suggests improvements if one exists); `CLAUDE_CODE_NEW_INIT=1` makes `/init` an interactive multi-phase flow that can also set up skills and hooks. `/init` also imports Cursor/Copilot rules; `/import` (v2.1.213+) brings another agent's config (AGENTS.md, MCP, commands, subagents, skills). — [Memory](https://code.claude.com/docs/en/memory)
- `/doctor prompt-audit` (v2.1.283+) audits CLAUDE.md/AGENTS.md/rules/skills/commands/subagents/output styles for outdated or conflicting content and proposes edits; `/doctor` checkup also proposes trims of a checked-in CLAUDE.md (v2.1.206+). — [Memory](https://code.claude.com/docs/en/memory)
- Rules: `.claude/rules/**/*.md` (recursive); without `paths` frontmatter they load at launch like `.claude/CLAUDE.md`; with `paths:` (globs, brace expansion) they load only when Claude reads/writes/edits a matching file; `paths` is the only frontmatter field read. User-level rules in `~/.claude/rules/`. Symlinks supported (outside targets need approval; network paths/UNC not followed). — [Memory](https://code.claude.com/docs/en/memory)
- AGENTS.md: read natively from v2.1.277 when there is no CLAUDE.md/CLAUDE.local.md on the path; `/config` → **Project instructions** = `claude-md-or-agents-md` (default) | `claude-md-and-agents-md` | `claude-md` | `managed-only`; implemented by built-in mod `cc-plugin-agents-md@builtin`. **Windows gotcha**: prefer `@AGENTS.md` import over a symlink, since symlinks need admin/Developer Mode and Git may check them out as one-line text files. — [Memory](https://code.claude.com/docs/en/memory)
- `claudeMdExcludes` (glob list, any settings layer, arrays merge) skips specific CLAUDE.md/rules files; managed CLAUDE.md can't be excluded; `claudeMd` key embeds managed CLAUDE.md text in managed settings only. — [Memory](https://code.claude.com/docs/en/memory)
- Auto memory: Claude writes notes typed `user`, `feedback`, `project`, `reference` in `~/.claude/projects/<project>/memory/` (per git repo, shared across worktrees, machine-local, not shared to cloud); `MEMORY.md` index — first 200 lines or 25 KB loaded every session; topic files read on demand; on by default in local sessions; toggle in `/memory` (`autoMemoryEnabled`), `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, or `autoMemoryDirectory` to relocate. "The main conversation's auto memory isn't loaded into subagents" (except forks). — [Memory](https://code.claude.com/docs/en/memory)
- `/memory` lists all memory files (creates missing ones on select), toggles auto memory, opens the auto-memory folder; `/context` shows which files loaded under **Memory files**. Asking "remember X" saves to auto memory; "add this to CLAUDE.md" edits CLAUDE.md. — [Memory](https://code.claude.com/docs/en/memory)
- After `/compact`, project-root CLAUDE.md is re-read from disk and re-injected; nested CLAUDE.md and path rules reload on demand; conversation-only instructions are lost. `InstructionsLoaded` hook logs what loaded and why. — [Memory](https://code.claude.com/docs/en/memory)
- `--add-dir` directories' CLAUDE.md don't load unless `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`. — [Memory](https://code.claude.com/docs/en/memory)

### Inferences
- Token lever for the user: keep the root CLAUDE.md of each guild short (<200 lines), move per-area guidance to `.claude/rules/` with `paths:` and procedures to skills; use HTML comments for human-only notes. Fixed NPC subagents that don't need project rules should set `omitClaudeMd: true` (see §6).
- Integration idea: each guild folder's `CLAUDE.md` is the "guild charter" (leader persona, delegation rules, roster summary) shown/edited from the game; the Reaper writes an NPC's "testament" into that NPC's `memory` directory (`.claude/agent-memory/<npc>/MEMORY.md`) so its apprentice inherits it automatically (§6).
- Portuguese: instructions can be written in Portuguese in CLAUDE.md (no doc restriction found); I found no doc stating a language effect on adherence.

### Gaps
- No official numeric "combined limit" for many CLAUDE.md files was given (only "a combined limit").

## 3. settings.json scopes, precedence, /config, and the env vars that matter

### Takeaway
Five levels (highest first): Managed → `--settings` (CLI, one session) → `.claude/settings.local.json` → `.claude/settings.json` → `~/.claude/settings.json`; lists such as `permissions.allow` merge across files; env vars are not a level (decided per pair). `/config` is terminal-only (Desktop app and VS Code don't open it). Most edits hot-reload; `model`/`effortLevel` don't (use `/model`, `/effort`). For cost, the key env vars are `CLAUDE_CODE_SUBAGENT_MODEL` (+ `_FORCE`), `CLAUDE_CODE_EFFORT_LEVEL`, `MAX_THINKING_TOKENS`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`/`CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `ENABLE_TOOL_SEARCH`, `MAX_MCP_OUTPUT_TOKENS`, `BASH_MAX_OUTPUT_LENGTH`.

### Cited findings
- Scopes: User `~/.claude/settings.json` (you, all projects); Shared project `.claude/settings.json` (commit it); Project local `.claude/settings.local.json` (auto-git-excluded when Claude Code creates it; stores "Yes, and don't ask again" approvals); Managed (`managed-settings.json`, MDM, or claude.ai console). On Windows `~/.claude` = `%USERPROFILE%\.claude`; `CLAUDE_CONFIG_DIR` relocates everything. `~/.claude.json` holds sign-in, MCP configs, per-project trust and "global config" keys. — [Settings](https://code.claude.com/docs/en/settings)
- Precedence: 1 Managed, 2 Command line `--settings <file-or-json>`, 3 Project local, 4 Shared project, 5 User. "Lists merge instead of overriding" (except `fallbackModel`, `modelPicker`, managed `availableModels`, `modelSettings`). — [Settings](https://code.claude.com/docs/en/settings)
- Windows-specific: "on Windows" the local file stays with `.claude/settings.json` (not moved to repo root) — listed among the cases where the local file isn't placed at the repository root. — [Settings](https://code.claude.com/docs/en/settings)
- `/config` menu → Config tab (theme, editor mode, verbose…), `/config key=value` sets one option (added Week 25, June 2026 per [What's new W25](https://code.claude.com/docs/en/whats-new/2026-w25)); **"`/config` is part of the terminal interface. The VS Code chat panel and the desktop app don't open it; change settings there by editing a settings file or through those apps' own settings."** In claude.ai/code `/config` opens claude.ai settings. — [Settings](https://code.claude.com/docs/en/settings)
- Hot reload: settings files are watched; edits to `permissions`, `hooks`, etc. apply mid-session (`ConfigChange` hook fires); `model` and `effortLevel`/`modelSettings` are read only at start. `/status` → "Setting sources"; `claude doctor` lists rejected entries. Strict JSON (no comments/trailing commas). `$schema: https://json.schemastore.org/claude-code-settings.json` gives editor autocomplete. — [Settings](https://code.claude.com/docs/en/settings)
- `permissions.defaultMode` values `auto` and `bypassPermissions` don't take effect from project/local settings (user/managed or `--permission-mode` only; since v2.1.257). Project `permissions.allow`, `additionalDirectories`, `extraKnownMarketplaces` and most `env` wait for workspace trust; `deny`/`ask` apply immediately. — [Settings](https://code.claude.com/docs/en/settings)
- Cloud sessions read only the repo's committed `.claude/settings.json` (single-repo sessions), not user or local settings; change them via environment variables on the cloud environment. — [Settings](https://code.claude.com/docs/en/settings)
- Env vars (all from [Environment variables](https://code.claude.com/docs/en/env-vars)):
  - `CLAUDE_CODE_SUBAGENT_MODEL` — default model for subagents, teammates, workflow agents not assigned another way (per-invocation `model` and frontmatter `model` win, unless `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`, v2.1.257+). [Sub-agents](https://code.claude.com/docs/en/sub-agents) shows `{"env":{"CLAUDE_CODE_SUBAGENT_MODEL":"haiku","CLAUDE_CODE_SUBAGENT_MODEL_FORCE":"1"}}` to run every subagent on Haiku.
  - `MAX_THINKING_TOKENS` — fixed thinking budget; `0` disables thinking on the Anthropic API "except on Opus 5.5, Sonnet 5.5, Haiku 5.5, and the Fable models, which can't have thinking turned off"; adaptive models choose depth when unset.
  - `CLAUDE_CODE_EFFORT_LEVEL` — `low|medium|high|xhigh|max|auto`; beats `--effort`, `/effort`, `effortLevel`, `modelSettings` (`maxEffortLevel` cap still applies).
  - `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` — 1–100, compact earlier (can't raise); applies to main conversation and subagents. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` — 100000–1000000 tokens (plain integer only).
  - `CLAUDE_CODE_MAX_OUTPUT_TOKENS` — raising it shrinks effective context before auto-compaction.
  - `DISABLE_PROMPT_CACHING=1` (don't); `ENABLE_PROMPT_CACHING_1H=1` — "Subscription users within included usage receive the 1-hour TTL automatically on the main conversation."
  - `ENABLE_TOOL_SEARCH` — unset = defer all MCP tools (default); `auto` loads upfront when tool defs fit in 10% of context; `auto:N`; `false` loads all upfront.
  - `MAX_MCP_OUTPUT_TOKENS` (default 25,000; warning above 10,000); `BASH_MAX_OUTPUT_LENGTH` (default 30,000 chars, max 150,000; `bashOutputMaxChars` setting wins); `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` (default 25,000).
  - `SLASH_COMMAND_TOOL_CHAR_BUDGET` — skill-metadata budget, "scales dynamically at 1% of the context window, with a fallback of 8,000 characters".
  - `CLAUDE_CODE_DISABLE_AUTO_MEMORY`, `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`, `CLAUDE_CODE_FORK_SUBAGENT` (fork mode; on by default interactive since v2.1.232), `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS` (v2.1.198+).
  - `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` — "Agent teams are experimental and disabled by default".
  - `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false` turns off grey prompt predictions; Claude Code already "pauses suggestions while your account is close to or at its usage limit".
  - `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`; `ANTHROPIC_DEFAULT_HAIKU_MODEL`/`_SONNET_`/`_OPUS_` remap aliases (Haiku alias also used for background functionality); `ANTHROPIC_SMALL_FAST_MODEL` deprecated.
  - Windows: `CLAUDE_CODE_USE_POWERSHELL_TOOL` ("On Windows without Git Bash, the tool is enabled automatically"; with Git Bash it's on by default for claude.ai and Console accounts), `CLAUDE_CODE_GIT_BASH_PATH` (path to `bash.exe`). `CLAUDE_CODE_SHELL` accepts bash/zsh only.
  - `DISABLE_TELEMETRY` (any non-empty value opts out, even `0`), `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`.

### Inferences
- For a Pro user, the cheapest global default is `CLAUDE_CODE_SUBAGENT_MODEL=haiku` (without FORCE) so that unassigned subagents/freelancers go to Haiku while NPC files can still pin `model: sonnet` where quality matters.
- Since the Desktop app doesn't open `/config`, the game itself (via `$.config.set` in the mod, §1) is a natural "settings panel" for the Desktop user.

## 4. Permissions and permission modes (/permissions, allow/ask/deny, Shift+Tab)

### Takeaway
Six modes: `default` (shown as **Manual**), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. Since v2.1.283 **auto mode is the built-in starting mode** for interactive terminal and VS Code sessions (earlier: only on Pro/Max/Team). Rules are evaluated deny → ask → allow (first match wins; specificity doesn't matter). Rules are enforced by the client, unlike CLAUDE.md. For a Pro user, auto mode's classifier checks run server-side at no extra charge ("Pro, Max, and Team plans never show the notice"). Important mod caveat: on a personal machine without managed settings, a mod's `tool.check` can approve calls that ask rules, PreToolUse hooks, the auto classifier — and even deny rules — would block.

### Cited findings
- Mode table: `default` = reads only run without asking; `acceptEdits` = reads, edits, and `mkdir/touch/rm/rmdir/mv/cp/sed` inside working dirs (PowerShell `Set-Content/Add-Content/Clear-Content/Remove-Item` too); `plan` = reads + classifier-approved commands when auto is available; `auto` = everything with background safety checks; `dontAsk` = only pre-approved tools, anything that would prompt is denied (for CI); `bypassPermissions` = everything (containers/VMs only). `manual` is accepted as alias of `default`. — [Permission modes](https://code.claude.com/docs/en/permission-modes)
- Built-in starting mode: "With Claude Code v2.1.283 or later, auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions. On earlier versions, it's the built-in starting permission mode only on Pro, Max, and Team plans." The built-in `auto` default requires v2.1.228+ on macOS/Linux/WSL and **v2.1.233+ on native Windows**. `claude -p`/SDK start in `default`. — [Permission modes](https://code.claude.com/docs/en/permission-modes); "auto mode becomes the default permission mode" — [What's new W32 (Aug 3–7, 2026)](https://code.claude.com/docs/en/whats-new/2026-w32); auto mode on the Pro plan — [What's new W21 (May 18–22, 2026)](https://code.claude.com/docs/en/whats-new/2026-w21)
- Switching: CLI `Shift+Tab` cycles auto → default → acceptEdits → plan (bypass only if started with it; `dontAsk` never in cycle). **Desktop**: mode selector next to the send button; Bypass requires the "Allow bypass permissions mode" toggle on Pro/Max; a mode picked in Desktop "is remembered per folder" (except Plan). Cloud sessions (claude.ai/code): Accept edits, Plan, Auto only. `/plan [task]` enters plan mode; `Ctrl+G` edits the proposed plan. — [Permission modes](https://code.claude.com/docs/en/permission-modes)
- Auto mode requirements: all plans; models Opus 4.6+, Sonnet 4.6+, Haiku 5.5, Fable on the Anthropic API; "Auto mode reduces permission prompts but does not guarantee safety"; it also reviews each `SendMessage` to another agent (v2.1.222+); `permissions.disableAutoMode: "disable"` removes it. `defaultMode: "auto"` is ignored in project/local settings — put it in `~/.claude/settings.json`. — [Permission modes](https://code.claude.com/docs/en/permission-modes)
- Classifier billing: server-side review is "at no charge"; the fallback notice appears when a gateway/proxy blocks it; "Pro, Max, and Team plans never show the notice." `/status` → "Auto mode server" row. — [Auto mode classifier billing](https://code.claude.com/docs/en/auto-mode-classifier-billing)
- Rules: `/permissions` dialog (also mid-turn, applies from the next tool call); format `Tool` or `Tool(specifier)`: `Bash(npm run *)`, `Read(./.env)`, `WebFetch(domain:example.com)`, `mcp__server`, `mcp__server__*`, `Agent(Explore)`, `Skill(name)`/`Skill(name *)`, `Cd(...)`. A bare-name deny (e.g. `Bash`) "removes the tool from Claude's context entirely". Parameter rules for deny/ask: `Agent(model:opus)`, `Agent(isolation:worktree)`, `Bash(run_in_background:true)`. Put `*` after the subcommand (`Bash(git log *)`). "Yes, and don't ask again" saves to `.claude/settings.local.json` (Bash/WebFetch permanent; file edits only until session end). — [Permissions](https://code.claude.com/docs/en/permissions)
- Hooks vs rules: PreToolUse hook decisions don't bypass deny/ask rules; exit-code-2 block beats allow rules. **Mods**: a mod's `tool.check` answers after rules and PreToolUse hooks and can approve calls that ask rules or (non-managed) PreToolUse hooks block, skip the auto classifier, and — "Anywhere else [no managed settings, not Team/Enterprise], the mod can approve a call that a deny rule refuses." — [Permissions](https://code.claude.com/docs/en/permissions)
- Actions no mode auto-approves: explicit ask rules, `AskUserQuestion`, MCP tools marked `requiresUserInteraction`, critical-path `rm`, cross-session messaging safeguards. — [Permission modes](https://code.claude.com/docs/en/permission-modes)
- Windows: on Windows the "don't ask again" rule isn't saved at the repo root (see settings note). — [Permissions](https://code.claude.com/docs/en/permissions)

## 5. Skills (SKILL.md), custom commands (.claude/commands), bundled skills, built-in commands

### Takeaway
Custom commands were merged into skills: `.claude/commands/x.md` and `.claude/skills/x/SKILL.md` both create `/x`. ## 6. Subagents (.claude/agents/*.md), built-in agents, forks, nesting, background

### Takeaway
A subagent is a Markdown file with YAML frontmatter (only `name` + `description` required) whose body is its whole system prompt; it runs in its own context window, counts toward the same plan limits, and returns only a summary. Key cost levers: `model` (haiku/sonnet), `effort`, `omitClaudeMd`, small `tools`, `mcpServers` scoped to the subagent, short descriptions (combined >15,000 tokens triggers a warning), and forks (share the parent's prompt cache). Since mid-2026 subagents run in the background by default (fork mode on in interactive sessions), can nest 3 levels deep, and up to 20 can run concurrently.

### Cited findings
- Scopes and priority: Managed (1) > `--agents` JSON flag (2, session only) > `.claude/agents/` (3, project; walks up to repo root) > `~/.claude/agents/` (4, user) > plugin `agents/` (5). Scanned recursively; identity = `name` only (plugin subfolders become part of the scoped id, e.g. `my-plugin:review:security`). Files are watched; a brand-new `agents` dir needs restart. PowerShell example for `--agents` uses a here-string `@' … '@`. — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- Full frontmatter table: `name` (≤256 chars, no `:`), `description` (required), `tools` (allowlist; `Agent(worker, researcher)` syntax restricts spawnable types only for a main-thread `--agent`), `disallowedTools` (denylist; `mcp__server`, `mcp__*` patterns), `model` (`sonnet|opus|haiku|fable|<full id>|inherit`), `permissionMode` (`default|acceptEdits|auto|dontAsk|bypassPermissions|plan`, `manual`=default), `maxTurns` (partial output marked, v2.1.246+), `skills` (preload full content, first 32), `mcpServers` (names or inline stdio/http/sse/ws configs), `hooks`, `memory` (`user|project|local`), `background` (true), `omitClaudeMd` (v2.1.271+), `effort` (`low|medium|high|xhigh|max`), `isolation` (`worktree`), `color` (`red|blue|green|yellow|purple|orange|pink|cyan`), `initialPrompt` (when run as main agent), `experimental: { cacheTtl: 5m|1h }` (v2.1.248+). ## 7. Settings hooks (hooks in settings.json / plugin hooks.json / skill & agent frontmatter)

### Takeaway
Settings hooks are deterministic handlers (5 types: `command`, `http`, `mcp_tool`, `prompt`, `agent`) that run at ~30 lifecycle events, receive JSON (stdin or POST body) and answer via exit codes (0 = ok, 2 = block where the event can block) or a JSON object. They cost zero tokens unless they inject text (`additionalContext`/plain stdout on SessionStart/UserPromptSubmit/etc., capped at 10,000 chars) or are `prompt`/`agent` hooks (which call a model — by default the background/Haiku-class model). For the game, `SessionStart` (resume cost fields), `SubagentStart/Stop`, `PreCompact/PostCompact`, `Notification` (quota auto-resume), `Stop`, `TeammateIdle`, `TaskCreated/TaskCompleted` are the useful events; inside a mod they are visible as `classic.<Event>`.

### Cited findings
- Full event list (when it fires): `SessionStart` (start/resume/clear/compact/fork), `Setup` (`--init-only`, `--init`/`--maintenance` in `-p`), `UserPromptSubmit`, `UserPromptExpansion` (slash command expansion; can block), `PreToolUse` (can block), `PermissionRequest`, `PermissionDenied` (auto-mode denials; `retry: true`), `PostToolUse`, `PostToolUseFailure`, `PostToolBatch` (after parallel batch, before next model call), `Notification`, `MessageDisplay` (display-only rewrite of streamed text), `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure` (API error ends turn), `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch` (can block), `PostModelSwitch`, `Elicitation`, `ElicitationResult`, `SessionEnd`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Locations: `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed, plugin `hooks/hooks.json`, skill frontmatter (rest of session once invoked; `once: true` supported only there), subagent frontmatter (while it runs). - Matchers: `"*"`/empty = all; letters/digits/`_-`/spaces/`,`/`|` = exact (list) match; anything else = unanchored JS regex (`^Edit$`). Per event: tool name (tool events), source (SessionStart: `startup|resume|clear|compact|fork`), notification type (`permission_prompt`, `idle_prompt`, `auth_success`, `elicitation_*`, `agent_needs_input`, `agent_completed`, `quota_auto_resume_fired`, `quota_auto_resume_stale`, `quota_auto_resume_disabled`), agent type (SubagentStart/Stop), `manual|auto` (Pre/PostCompact), model name (Pre/PostModelSwitch), error type (StopFailure: `rate_limit`, `overloaded`, `billing_error`, `max_output_tokens`…). - Handler fields: common `type`, `if`, `timeout` (defaults 600 s command/http/mcp_tool; 30 s prompt; 60 s agent; 30 s on UserPromptSubmit/Pre/PostModelSwitch; SessionEnd shares 1.5 s), `statusMessage`, `once`. Command: `command`, `args` (exec form, no shell), `async`, `asyncRewake` (wake Claude on exit 2), `shell` (`bash`|`powershell`; default powershell on Windows without Git Bash), `onFailure: "block"` (v2.1.295+). HTTP: `url`, `headers`, `allowedEnvVars`. MCP tool: `server`, `tool`, `input` (`${tool_input.file_path}` substitution). Prompt/agent: `prompt` (`$ARGUMENTS`), `model` (default = background-functionality model). All matching hooks run in parallel. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Exit codes: 0 = success (JSON applied; plain stdout added as context only on `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, `PostModelSwitch`); 2 = blocking error with stderr as reason (blockable: PreToolUse, UserPromptSubmit, UserPromptExpansion, Stop, SubagentStop, TeammateIdle, TaskCreated, TaskCompleted, ConfigChange, PostToolBatch, PreCompact, PreModelSwitch, Elicitation*, Worktree*); other codes = non-blocking error ("exit code 1 [is] a non-blocking error… use `exit 2`"). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- JSON output: universal `continue` (false = stop), `stopReason`, `systemMessage` (shown to user), `terminalSequence` (OSC 0/1/2/9/99/777 + BEL; works on Windows Terminal via OSC 9), `suppressOutput` (no effect); `decision: "block"` + `reason` (UserPromptSubmit, PostToolUse, Stop, SubagentStop, ConfigChange, PreCompact…); `hookSpecificOutput` with `permissionDecision` (`allow|deny|ask|defer`), `updatedInput` (PreToolUse), `updatedToolOutput` (PostToolUse), `additionalContext`. `additionalContext`/`systemMessage`/plain stdout capped at 10,000 chars each (overflow saved to a file with a 2,000-char preview). Write context as factual statements, not "system commands" (can trigger prompt-injection defenses). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- SessionStart: only `command` and `mcp_tool` types; runs in background at interactive start; `CLAUDE_ENV_FILE` to persist env vars (PowerShell gets plain assignments only, v2.1.296+); output fields `additionalContext`, `initialUserMessage` (`-p` only), `sessionTitle`, `watchPaths` (for FileChanged), `reloadSkills`. - Prompt hooks send hook input + prompt to the background-functionality model and expect a JSON decision; agent hooks (`type: "agent"`) "are experimental", spawn a subagent with Read/Grep/Glob for up to 50 turns and return `{ "ok": true|false, "reason" }`. Supported on PreToolUse, PostToolUse(Failure), PostToolBatch, PermissionDenied, Stop, SubagentStop, TaskCreated, TaskCompleted, TeammateIdle, UserPromptSubmit, UserPromptExpansion (PermissionRequest: prompt but not agent). — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Async: `"async": true` (command only) runs in background, can't block; its `additionalContext`/`systemMessage` reach Claude on the next turn; `asyncRewake` exit 2 wakes Claude immediately. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Windows: `"shell": "powershell"` (auto-detects `pwsh.exe`, falls back to `powershell.exe`); exec form on Windows needs a real `.exe` (npm `.cmd` shims need shell form or `node script.js`); official example uses `"command": "powershell.exe", "args": ["-NoProfile","-ExecutionPolicy","Bypass","-File","${CLAUDE_PROJECT_DIR}/.claude/hooks/x.ps1"]` and matcher `Bash|PowerShell`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Hook vs mod: settings hooks can't draw UI; mods can and see these events as `classic.*`. — [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)

### Inferences
- Token-saving hooks for the user: (a) a `PreCompact` hook with matcher `auto` that saves `transcript_path` + state to a file the leader reloads (cheap continuity); (b) a `SessionStart` (`resume`) hook that warns via `systemMessage` when `prompt_cache_likely_expired` is true and `context_tokens` is large ("this guild woke up cold: ~N tokens to re-read; consider /clear + handoff"); (c) a `PostToolUse` hook that trims noisy tool output with `updatedToolOutput`; (d) avoid `prompt`/`agent` hooks on frequent events (each fires a model call).
- Reaper via settings hooks (if not using the mod): `SubagentStop` gives `agent_transcript_path` + `last_assistant_message` to archive an NPC's final report; `PostCompact.compact_summary` is a ready-made "memoir" of a leader's era.
- On Windows prefer exec form with `node` or `powershell.exe -File`, and remember plain-text stdout only reaches Claude on a few events.

### Gaps
- No doc states the exact model used for "background functionality" on a Pro plan beyond the `ANTHROPIC_DEFAULT_HAIKU_MODEL` mapping (see §11).

## 8. Plugins and plugin marketplaces (/plugin)

### Takeaway
A plugin is a folder (`.claude-plugin/plugin.json` manifest) that bundles skills, commands, agents, hooks, a hooks module (= mod), MCP servers, LSP servers, executables in `bin/`, default settings (`agent`, `subagentStatusLine`), themes, output styles, channels and monitors; installed from marketplaces (`.claude-plugin/marketplace.json` in a repo) at user/project/local scope. Every enabled plugin adds the names+descriptions of its model-invocable skills/agents/commands to every turn ("always-on" cost) — measure with `claude plugin details <name>` and prune with `/plugin` → Installed → "Not used recently". Cloud sessions (claude.ai/code) don't load your plugins at all.

### Cited findings
- Components: skills (`skills/<name>/SKILL.md` → `/plugin:skill`), commands (`commands/*.md`, older format), agents (`agents/*.md`, scoped `plugin:name`; `hooks`/`mcpServers`/`permissionMode` ignored), hooks (`hooks/hooks.json`), hooks module (mod), MCP servers (`.mcp.json` or manifest `mcpServers`), LSP servers, **executables** (`bin/` on the Bash tool's PATH, after the user's own entries), **default settings** (`settings.json` at plugin root; only `agent` and `subagentStatusLine` take effect), **themes** (`themes/<slug>.json`, manifest `experimental.themes`), **output styles** (`output-styles/<name>.md` → `/output-style <plugin>:<name>`), **channels** (MCP server that pushes messages in), **monitors** (`monitors/monitors.json`: background shell commands whose output reaches Claude as notifications). — [Plugins overview](https://code.claude.com/docs/en/plugins/overview); [Plugin components](https://code.claude.com/docs/en/plugins/components)
- Path variables: `${CLAUDE_PLUGIN_ROOT}` (changes per version; don't write state), `${CLAUDE_PLUGIN_DATA}` = `~/.claude/plugins/data/<id>/` (survives updates), `${CLAUDE_PROJECT_DIR}`; "On Windows, the substituted paths use forward slashes". `userConfig` options are prompted in `/plugin` (or `claude plugin install --config KEY=VALUE`, `claude plugin configure --values-stdin`), stored under `pluginConfigs`. — [Plugin components](https://code.claude.com/docs/en/plugins/components)
- Cost: "for each skill, agent, and command that Claude can invoke on its own, the name and description are in Claude's context on every turn… even in sessions where nothing from the plugin runs." `claude plugin details <name>` prints "Projected token cost — Always-on: ~146 tok added to every session" plus per-component on-invoke cost; hooks are "harness-only — no model context cost"; MCP schemas not counted (see `/context` → MCP tools). Official-marketplace plugins show **Context cost** (`Every turn:` / `When invoked:`) before install, highlighted at ≥2,000 tokens. "Not used recently" after ≥14 days and 10 sessions. `/usage` on Pro attributes usage share to skills, subagents, plugins and MCP servers. — [Measure plugin cost](https://code.claude.com/docs/en/plugins/measure); [Plugins overview](https://code.claude.com/docs/en/plugins/overview)
- Install: terminal `/plugin` (Discover/Installed/Marketplaces/Errors tabs), `/plugin install name@marketplace`, shell `claude plugin install|list|enable|disable|update|validate|details|eval|test`; **Desktop app**: Code tab → **+** next to the prompt → **Plugins** → **Add plugin**, manage via **+ > Plugins > Manage plugins** (not in Desktop cloud sessions); VS Code: `/plugins`. Scopes: user (all projects; shared by terminal, Desktop local sessions and VS Code on the same computer), project (committed `.claude/settings.json`), local. Install summary may say "Run /reload-plugins to apply"; `/reload-plugins --force` "costs one uncached request" when it changes MCP tools. — [Install plugins](https://code.claude.com/docs/en/plugins/install); [Plugins overview](https://code.claude.com/docs/en/plugins/overview)
- Cloud: "A cloud session… has no plugin browser and doesn't load the plugins you installed on your own machine or the ones your repository's `.claude/settings.json` turns on." — [Install plugins](https://code.claude.com/docs/en/plugins/install); confirmed in the cloud table ("Plugins and marketplaces declared in your repo's `.claude/settings.json` — No") — [Cloud environments](https://code.claude.com/docs/en/cloud-environments)
- Marketplaces: official `claude-plugins-official` is added automatically on first interactive terminal session; community/demo ones are opt-in; any other is "third-party". A plugin runs code with your privileges. — [Plugins overview](https://code.claude.com/docs/en/plugins/overview)
- `claude plugin eval` (What's new W37, Sept 7–11 2026) scores a plugin with vs. without. — [What's new W37](https://code.claude.com/docs/en/whats-new/2026-w37)

### Inferences
- The game itself should ship as one plugin (mod + its own `agents/` NPC definitions + skills + optional `bin/` helper + `output-styles/` "narrator" style + theme), installed at **user** scope from a terminal so the Desktop app picks it up. Keep NPC/skill descriptions very short to minimise "always-on" tokens; check with `claude plugin details <rpg>`.
- Leonardo da Vinho as a plugin MCP server or `bin/` script (e.g. `bin/pintar`) means the image API key can come from `userConfig` (`sensitive: true`) rather than being hard-coded.

### Gaps
- No doc gives a Windows-specific install caveat for plugins beyond path slashes; `/plugin install` is unavailable inside the Desktop Code tab per the local mod reference (use the Desktop "+ > Plugins" UI or a terminal).

## 9. MCP (servers, scopes, tool search, per-subagent servers, context cost)

### Takeaway
MCP servers are added with `claude mcp add` at local (default, `~/.claude.json` per project), project (`.mcp.json`, committed) or user scope; claude.ai connectors (e.g. the user's Canva/Supabase/GitHub connectors) appear automatically when logged in with a subscription. Tool search is ON by default: only tool names (+ server instructions) load at start and schemas are fetched on demand — so many servers cost little until used. `alwaysLoad: true` puts a server's tools upfront (costs context every turn). Defining a server inline in one subagent's `mcpServers` keeps its tools out of the main context entirely.

### Cited findings
- Add: `claude mcp add [--transport http|sse|stdio|ws] [--scope local|project|user] [--env K=V] <name> -- <command> [args]` (the `--` separates server args), remote `claude mcp add --transport http name https://…`; JSON via `claude mcp add-json`; `/mcp` to manage/authenticate (`reconnect`, `enable`, `disable`); `claude mcp login`. Precedence: local > project > user > plugin > claude.ai connectors (no field merge). Project `.mcp.json` servers need approval in interactive sessions. — [MCP](https://code.claude.com/docs/en/mcp)
- Windows: `~/.claude.json` = `%USERPROFILE%\.claude.json`. "Import MCP servers from Claude Desktop… only works on macOS and Windows Subsystem for Linux (WSL)". — [MCP quickstart](https://code.claude.com/docs/en/mcp-quickstart); [MCP](https://code.claude.com/docs/en/mcp)
- Tool search: "Only tool names and server instructions load at session start, so adding more MCP servers has minimal impact on your context window"; tool descriptions/server instructions truncated at 2,048 chars (`CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`, v2.1.280+); `ENABLE_TOOL_SEARCH` unset/true/`auto`/`auto:N`/false; per-server `"alwaysLoad": true` ("each upfront tool consumes context") or `false` (v2.1.287+); per-tool `_meta["anthropic/alwaysLoad"]`. Requires models with `tool_reference` support (Sonnet/Haiku/Opus 4.5+). — [MCP](https://code.claude.com/docs/en/mcp)
- Output limits: warning above 10,000 tokens; default max 25,000 (`MAX_MCP_OUTPUT_TOKENS`); text results >50,000 chars saved to a file under `~/.claude/projects/…/tool-results`; per-tool `anthropic/maxResultSizeChars`. — [MCP](https://code.claude.com/docs/en/mcp)
- claude.ai connectors: added at claude.ai/customize/connectors, appear in `/mcp` only when the active auth is a claude.ai subscription login (not with `ANTHROPIC_API_KEY` etc.); not available in Desktop WSL sessions; a locally added server with the same URL hides the connector. — [MCP](https://code.claude.com/docs/en/mcp)
- Per-subagent: `mcpServers` in agent frontmatter (string = share parent's connection; inline = connected at subagent start and disconnected after; "To keep an MCP server out of the main conversation entirely and avoid its tool descriptions consuming context there, define it inline here rather than in `.mcp.json`"). — [Sub-agents](https://code.claude.com/docs/en/sub-agents)
- Cloud sessions load the repo's `.mcp.json` (single-repo sessions) but not servers added at local/user scope; on Pro and Max, API keys can be stored as **network secrets** on the cloud environment. — [Cloud environments](https://code.claude.com/docs/en/cloud-environments)
- Mods can call MCP tools directly with `$.mcp.call(server, tool, args)` (no permission prompt; "the plugin's call… is the grant") and connect servers their own manifest lists with `$.mcp.connect`. — [DTS](file:///tmp/claude-0/bundled-skills/2.1.296/35d2bed4a892af6e0bfe7efcd8e601d2/plugin-authoring/types/claude-code.d.ts)
- Channels: an MCP server can push messages/webhooks into a running session (`/docs/en/channels`). — [Channels](https://code.claude.com/docs/en/channels)

### Inferences
- Leonardo da Vinho: give the painter subagent an inline `mcpServers` entry for the image-generation server (or the Canva connector by name) so only that NPC pays for those tool definitions; the leader never sees them.
- For cloud sessions, put the image MCP server in the repo's `.mcp.json` (`--scope project`) and its key as a network secret.

### Gaps
- No per-tool token figures are published for deferred vs. loaded MCP tools (use `/context` → MCP tools).

## 10. Output styles, status line (/statusline), subagent status lines, keybindings, themes, /config

### Takeaway
Output styles change Claude's voice for the whole session (built-ins: Default, Proactive, **Concise** (v2.1.237+, fewer output tokens), Explanatory, Learning; custom `.md` files in `~/.claude/output-styles` or `.claude/output-styles`). The status line is a local script fed rich JSON (context %, cost, 5-hour/7-day rate-limit %, prompt-cache warmth) and "does not consume API tokens"; `subagentStatusLine` renders one row per subagent with its own token count. Keybindings live in `~/.claude/keybindings.json` (hot-reloaded; includes `Pane`/`AbovePrompt` contexts for mods). Themes are JSON in `~/.claude/themes/` (plugins can ship them). In the Desktop app, `/config` opens Settings > Claude Code instead of the terminal menu, so styles are set via `outputStyle` in settings.

### Cited findings
- Output styles: apply to main conversation and forks only (not other subagents); "A style's instructions add input tokens, though prompt caching reduces this cost"; Explanatory/Learning produce longer responses "which increases output tokens. The Concise style does the opposite". Set with `/output-style <style>` (v2.1.269+), `/config` → Output style, or `"outputStyle": "Concise"` (case-sensitive) in settings; Desktop: set `outputStyle` in a settings file. Custom frontmatter: `name`, `description`, `keep-coding-instructions` (default false → drops the built-in software-engineering section), `force-for-plugin`. Mid-session switch applies from the next message (v2.1.251+). — [Output styles](https://code.claude.com/docs/en/output-styles)
- Concise style added in Week 34 (Aug 17–21, 2026). — [What's new W34](https://code.claude.com/docs/en/whats-new/2026-w34)
- Status line: `/statusline <description>` generates a script in `~/.claude/` and updates settings; manual `"statusLine": {"type":"command","command":"~/.claude/statusline.sh","padding":2,"refreshInterval":N}`; "runs locally and does not consume API tokens"; updates on new assistant message, `/compact`, mode change, etc. (300 ms debounce). — [Status line](https://code.claude.com/docs/en/statusline)
- Status line JSON fields: `model.*`, `workspace.*`, `cost.total_cost_usd` (client-side list-price estimate), `cost.total_duration_ms`, `context_window.used_percentage`/`remaining_percentage`/`context_window_size`/`current_usage`, `exceeds_200k_tokens`, `fast_mode`, `effort.level`, `thinking.enabled`, `rate_limits.five_hour.used_percentage`/`resets_at`, `rate_limits.seven_day.used_percentage`/`resets_at` ("only present for claude.ai Pro and Max subscribers… after the first API response"), `prompt_cache` {`warm`, `ttl` 5m|1h, `expires_at`, `hit_ratio`, `misses`, `last_miss_cause` (e.g. `tools_changed`, `system_prompt_changed`, `ttl_expired_5m`), `recache_tokens_if_cold`} (v2.1.251+), `session_name`, `output_style.name`, `agent.name`, `pr.*`, `worktree.*`. — [Status line](https://code.claude.com/docs/en/statusline)
- **Windows**: status line commands run through Git Bash if installed, else PowerShell; write paths with forward slashes (backslashes get eaten by Git Bash); invoke PowerShell scripts via `powershell`. — [Status line](https://code.claude.com/docs/en/statusline)
- `subagentStatusLine` (settings or plugin `settings.json`): receives all visible subagent rows (`tasks[]` with `id`, `name`, `agentType` (v2.1.293+), `status`, `description`, `label`, `model`, `effort`, `contextWindowSize`, `tokenCount`, `tokenSamples` (last 16), `cwd`) and prints `{"id": "...", "content": "..."}` per row. — [Status line](https://code.claude.com/docs/en/statusline)
- Keybindings: `/keybindings` opens `~/.claude/keybindings.json` (`bindings` array of `{context, bindings}`; `null` unbinds; auto-reloaded). Contexts include `Global`, `Chat`, `Confirmation`, `Transcript`, `Task`, `DiffPanel`, `ModelPicker`, `EffortSlider`, `Plugin`, `AbovePrompt`, `AbovePromptInput`, `AbovePromptSelect`, `Pane`, `PaneField`, `Agents`. Mod-related defaults: `abovePrompt:toggle` Ctrl+X Ctrl+A, `abovePrompt:focus` Ctrl+X Tab, `pane:grow`/`shrink` Ctrl+X arrows, `pane:close` Ctrl+X X, `pane:next/previous` unbound. Windows: image paste is Alt+V. — [Keybindings](https://code.claude.com/docs/en/keybindings)
- Themes: `/theme` (auto, light/dark, daltonized, ANSI, custom); custom theme JSON in `~/.claude/themes/<slug>.json` with `name`, `base` (`dark|light|dark-daltonized|light-daltonized|dark-ansi|light-ansi`), `overrides` (tokens like `claude`, `planMode`, `diffAdded`, `userMessageBackground`); hot-reloaded; plugins ship themes in `themes/`. — [Terminal config](https://code.claude.com/docs/en/terminal-config); [Plugin components](https://code.claude.com/docs/en/plugins/components)

## 11. Token/cost levers: models, effort, context window & auto-compaction, prompt caching, /usage (Pro plan focus)

### Takeaway
On a Pro plan the biggest levers are: (1) the model — `default` now resolves to **Opus 5.5 on Pro** (since v2.1.280; before it was Sonnet 5), so explicitly choosing `sonnet`/`haiku` for routine work matters; (2) context size — current models run a **1M-token window by default** and auto-compact only near the limit, so every request re-sends a potentially huge history (at cached rates); setting `/autocompact 200k` (or `autoCompactWindow`) and using `/clear` between tasks keeps each request small; (3) effort (`medium` is already the default on Opus/Sonnet/Haiku 5.5); (4) cache hygiene — avoid mid-session model/effort switches, plugin/MCP toggles, and long idle gaps (>1h main conversation; subagents only 5 min); (5) delegation to cheap subagents and skills instead of a fat CLAUDE.md. `/usage` on Pro shows plan bars plus an attribution breakdown (skills, subagents, plugins, MCP servers, loops) and flags behaviors ≥10% of usage.

### Cited findings
- `default` model: "Pro, Max, Team, Enterprise, and Anthropic API: defaults to Opus 5.5"; "Before v2.1.280, `default` resolved to Sonnet 5 on Pro and Team Standard". Aliases on the Anthropic API: `opus` = Opus 5.5, `sonnet` = Sonnet 5.5, `haiku` = Haiku 5.5; `fable` = Fable 5.1 (most capable, never the default; "Depending on your plan and seat tier, Fable usage can bill to usage credits… the `/model` picker shows 'Requires usage credits'"); `best`; `opusplan` (Opus in plan mode, Sonnet for execution — each toggle is a model switch/cache miss). Sonnet 5.5 needs v2.1.284+, Opus 5.5 v2.1.280+, Haiku 5.5 v2.1.293+. — [Model configuration](https://code.claude.com/docs/en/model-config)
- Effort: levels `low|medium|high|xhigh|max` (+ `ultracode` toggle = dynamic workflows, more spend); defaults: `medium` on Opus 5.5/Sonnet 5.5/Haiku 5.5, `high` elsewhere; "In Anthropic's testing, Opus 5.5 at `medium` matches or exceeds Opus 5 at `high`"; `max` applies to the session only and "is prone to overthinking"; `ultrathink` keyword = one-off deeper reasoning. Set via `/effort`, `/model` arrows, `--effort`, `CLAUDE_CODE_EFFORT_LEVEL`, `modelSettings`, skill/subagent `effort`. — [Model configuration](https://code.claude.com/docs/en/model-config)
- Thinking: "Thinking tokens are billed as output tokens… can't turn off thinking on Opus 5.5, Sonnet 5.5, Haiku 5.5, or the Fable models"; lower effort instead. — [Costs](https://code.claude.com/docs/en/costs)
- Extended context: Fable 5.x, Sonnet 5+, Haiku 5.5, Opus 4.7+ "run with the 1M window by default"; on Pro, Opus 4.6/Sonnet 4.6 `[1m]` variants require usage credits; Haiku 5.5 "costs more per token when its prompt is longer than 100K tokens" and auto-compacts at ~967K by default. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` holds models to 200K. — [Model configuration](https://code.claude.com/docs/en/model-config)
- Auto-compact window: `/autocompact 500k` (100K–1M; saved per model in `modelSettings`), `autoCompactWindow` setting, `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`; "If you don't set an auto-compact window, Claude Code compacts when the conversation reaches the model's context limit" (cloud sessions compact as they approach it). — [Model configuration](https://code.claude.com/docs/en/model-config)
- Why usage climbs: "Claude Code sends your full conversation with every request… a one-line question in a session that has been open all day still draws usage for the whole conversation"; cache misses after breaks ("lifetime is an hour on a subscription and drops to five minutes once you're drawing on usage credits"); scheduled tasks, cross-session messages (`crossSessionInbound: "hold"`), goal check-ins (max 3 idle check-ins; `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0`), subagents/workflows, teammates, compaction ("`/clear` costs nothing"). On Pro/Max, resuming a large session after a long break offers "resume from a summary". — [Costs](https://code.claude.com/docs/en/costs)
- `/usage` on Pro: plan usage bars, attribution to "skills, subagents, plugins, and individual MCP servers", behavior flags at ≥10%, Loops rows (v2.1.242+), `d`/`w` toggles 24h/7d; local machine only. Session dollar figure "isn't relevant for billing" for Pro/Max. `Prompt cache (main)` line (v2.1.251+). Spinner shows live output-token count per turn. `/insights` writes an HTML report to `~/.claude/usage-data/report.html` (costs tokens). — [Costs](https://code.claude.com/docs/en/costs)
- Limits messages: "You've hit your session limit"/"weekly limit" are shared across models (switching model doesn't help); model-specific "Opus limit" can be bypassed by `/model sonnet`; v2.1.234+ can "wait and continue the interrupted task automatically after the reset" (`/rate-limit-options`, `autoContinueAtUsageLimit`); Desktop auto-continues after a usage-limit reset (What's new W33, Aug 10–14 2026). — [Costs](https://code.claude.com/docs/en/costs); [What's new W33](https://code.claude.com/docs/en/whats-new/2026-w33)
- Reduce tokens (official list): `/clear` between tasks; custom `/compact <focus>` or a "# Compact instructions" section in CLAUDE.md; Sonnet for most tasks, `model: haiku` for simple subagents; prefer CLI tools (`gh`) over MCP; disable unused MCP servers; code-intelligence (LSP) plugins; hooks that pre-filter output (e.g. test output to failures only via `updatedInput`); move CLAUDE.md procedures to skills (<200 lines); lower effort; delegate verbose work to subagents; plan mode for complex tasks; Esc + `/rewind` early; specific prompts. Background usage "typically under $0.04 per session"; prompt suggestions reuse cache and pause near limits. — [Costs](https://code.claude.com/docs/en/costs)
- Agent teams: "approximately 7x more tokens than standard sessions when teammates run in plan mode"; keep teams small, use Sonnet for teammates. — [Costs](https://code.claude.com/docs/en/costs)
- Prompt caching: actions that invalidate — switching models (each model its own cache; `/model` asks while warm), changing effort (except Opus/Sonnet/Haiku 5.5 and Fable 5.1 on API/subscription, which keep the cache), turning on fast mode, connecting/removing an MCP server, enabling/disabling a plugin, denying a whole tool, compaction, many images, upgrading Claude Code. Actions that keep it — editing files, editing CLAUDE.md mid-session (but the edit doesn't apply until `/clear`, `/compact` or restart), changing permission mode, changing output style, invoking skills/commands, `/recap`, `/rewind`, spawning a subagent. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- TTLs: subscription within plan usage → main conversation 1 hour; "Everything else" (subagents, workflows, teammates, forks, compaction) 5 minutes; usage credits/API → 5 minutes. Override with `promptCacheTtl` / `subagentPromptCacheTtl` (`5m|1h`, v2.1.242+), env `CLAUDE_CODE_PROMPT_CACHE_TTL`, `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`, subagent `experimental.cacheTtl`. 1h cache writes cost more. Forks and resumed subagents read the existing cache; a fresh subagent warms its own. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Compaction cost: a warm-cache `/compact` "costs a fraction of what the context size suggests"; a cold one "reprocesses the full history as uncached input"; run `/compact` at natural breaks or `/rewind` to abandon a path (rewind hits the earlier cache). What survives compaction: system prompt/output style, project-root CLAUDE.md + unscoped rules + auto memory (re-injected), fresh git status, plan file, up to 5 recently modified files re-read (>5,000 tokens become references), skill bodies (5,000/skill, 25,000 total), SessionStart hooks with `compact` source re-run. — [Prompt caching](https://code.claude.com/docs/en/prompt-caching); [Context window](https://code.claude.com/docs/en/context-window)
- Plan availability (Pro ✓): cloud sessions, routines, Remote Control, channels, computer use, Dispatch (Desktop), artifacts; Pro ✗: Code Review (Team/Enterprise), analytics dashboard, server-managed settings. `/ultrareview`: 3 free runs on Pro/Max then usage credits. — [Feature availability](https://code.claude.com/docs/en/feature-availability); [Commands](https://code.claude.com/docs/en/commands)
- Other model features: fast mode (`/fast`, faster Opus at extra cost; toggling it is a cache miss), advisor tool (`/advisor [fable|opus|sonnet|off]`: a stronger model consulted at key moments). — [Commands](https://code.claude.com/docs/en/commands); [Prompt caching](https://code.claude.com/docs/en/prompt-caching)

### Inferences
- Recommended Pro baseline (all documented knobs): `"model": "sonnet"` (or `/model sonnet`) as default with Opus/Fable only on demand; `/autocompact 200k`; `"outputStyle": "Concise"`; `CLAUDE_CODE_SUBAGENT_MODEL=haiku` (without FORCE) and `model: haiku` on read-only NPCs; `/clear` between unrelated tasks; avoid mid-session model/effort flips; `crossSessionInbound: "hold"` if guild sessions message each other a lot; turn prompt suggestions off if desired.
- Reaper calibration: with 1M windows, "age" should be measured against the chosen auto-compact window (e.g. 200K), not the 1M model window — the mod's `$.session.usage().context.percent` is relative to the full window, so the game should compute `tokens / chosenWindow` itself. Retiring an NPC before compaction (hand-off + `/clear` or a fresh subagent) avoids paying for a large cold compaction.
- Show cache state in the game ("🔥 cache quente / ❄ frio") from `prompt_cache.warm/expires_at` (status line) or `turn.step` usage — waking a guild after >1h costs a full re-read.

### Gaps
- No official per-plan token numbers for Pro's 5-hour/weekly windows (only percentages are exposed via `rate_limits`).
- The docs page "Choosing a Claude model and effort level in Claude Code" is a blog post (claude.com/blog) I did not fetch.

## 12. Other features from the docs index: parallel work (Projects, agent view, agent teams, workflows, cross-session messaging), automation (routines, /loop, /goal, channels), sessions, checkpoints, Desktop specifics

### Takeaway
Besides subagents there are five ways to run work in parallel; for the user's "guild" model the closest built-ins are **Projects** (a coordinator conversation that spawns threads; public beta on Pro/Max; cloud-first; Opus everywhere by default → burns Pro limits fast), **cross-session messaging** (guild-to-guild messages; native Windows v2.1.234+), and **agent teams** (experimental, CLI-only, ~7× tokens in plan mode). For a Pro user, subagents + skills inside one session per guild remain the cheapest pattern. Desktop on Windows supports panes (chat/diff/terminal/plan/tasks/subagent), split sessions, cross-session management and plugin install via UI, but not agent teams, `/permissions`, or `/config key=value`.

### Cited findings
- Five approaches: Subagents; Agent view (`claude agents`, **research preview**, background sessions on your machine); Agent teams ("Experimental and disabled by default"; `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`); Projects ("Public beta on Pro and Max"); Dynamic workflows (script orchestrating many subagents). ### Inferences
- "Guild = one session per project folder" fits Desktop local sessions; guild-to-guild interaction can use cross-session messaging (Desktop's own "work across sessions" surface sees only Desktop-run sessions). Set `crossSessionInbound: "hold"` for guilds that shouldn't wake up (cost).

### Gaps

## 13. Consolidated caveats (Windows / Pro), version timeline, and game-integration blueprint

### Takeaway
For a Windows Desktop + Pro user building a mod-based RPG: install/run the mod from a user-scope plugin (terminal install or `CLAUDE_CODE_PLUGIN_DIRS` with `;` separators), expect the UI only in the Desktop Code tab and terminals (not cloud, not WSL, not VS Code), avoid terminal-only elements (`Raster`, `Image`) and sounds, prefer exec-form/PowerShell hooks, and drive cost from the mod with `session.measure` + `agent.spawn` model rewriting + per-NPC `autoCompactWindow`/`memory`.

### Inferences (game-integration blueprint, one idea per feature)
- **CLAUDE.md** → "Carta da Guilda": ≤200 lines per guild with leader persona and delegation rules ("delegue tarefas verbosas; use NPCs baratos"); path rules per area; HTML comments for lore notes that cost no tokens.
- **Auto memory / agent memory** → each NPC has `memory: project` so its `.claude/agent-memory/<npc>/MEMORY.md` is its "diário"; the Reaper writes the testament there for the apprentice (same directory name or copied).
- **settings.json / env** → a "Pergaminho de Economia" preset applied by the game: `model: sonnet`, `outputStyle: Concise`, `autoCompactWindow: 200000`, `CLAUDE_CODE_SUBAGENT_MODEL: haiku`, `crossSessionInbound: hold`.
- **Permissions/modes** → stance selector (Plan = conselho, Auto = campanha) via `$.config`/mode UI; deny `Agent(model:opus)` as an "anti-gastança" rune; never auto-approve via `tool.check` in the mod (on Pro it can override deny rules).
- **Skills/commands** → NPC abilities as skills (`/pintar-asset`, `/relatorio-guilda`) with `disable-model-invocation: true` (zero listing cost) or `context: fork` + `agent: <npc>`.
- **Subagents** → fixed NPCs in `.claude/agents/*.md` with `color`, `model: haiku|sonnet`, `effort`, `omitClaudeMd: true`, minimal `tools`, `autoCompactWindow` (v2.1.296) as "vida máxima", `maxTurns` as stamina; freelancers via `$.agent.register` + `$.agent.spawn` hidden with `agent.offer`.
- **Hooks** → `SubagentStop` archives each NPC's last report; `PreCompact`/`PostCompact` save the leader's "memórias" (`compact_summary`); `SessionStart(resume)` warns about cold-cache cost (`estimated_cache_write_usd`); `Notification` `quota_auto_resume_*` shows "a guilda voltou do descanso".
- **Plugins** → ship the whole RPG as one plugin (mod + agents + skills + theme + output style + optional `bin/` tool), user scope, short descriptions; check `claude plugin details`.
- **Mods** → Mega Brain pane from `$.agent.list()` (`parentId`, `status`, `type`) + `agent.spawn` events; stamina bar from `session.measure` (`seven_day`/`five_hour` `percentUsed`, `resetsAt`); per-NPC age from `turn.complete`/`turn.step` usage with `agentId`; cheap narration via `$.model.complete({model:'haiku'})` with cached static lore blocks; Reaper via `$.model.fork` + `$.session.compact({instructions})`; buttons that run `/compact`, `/usage`, `/context` through `$.command.run`; persist game state in `$.store` (4 MiB, shared by all guild sessions on the machine).
- **MCP** → Leonardo da Vinho's image API as an inline `mcpServers` entry in the painter's agent file (only he pays for the tool schemas), or a mod-registered `mcp__<rpg>__pintar` tool served by `$.http.fetch`.
- **Output styles** → a short Portuguese "Narrador" style with `keep-coding-instructions: true` for the leader only (subagents ignore styles).
- **Status line / subagentStatusLine** → zero-token HUD: guild name, context %, 7-day %, cache warm/cold; one row per NPC with "vida" = `tokenCount/contextWindowSize`.
- **Keybindings/themes** → bind `pane:next` (unbound by default) to switch game panes; one theme per guild shipped in the plugin.
- **Cross-session messaging** → "diplomacia entre guildas" (`$.session.send({to:{sessionId}})`), with `hold` to avoid waking idle guilds.
